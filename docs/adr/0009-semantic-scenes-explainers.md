# ADR 0009: Native semantic scenes with optional explainer adapters

Date: 2026-10-09. Status: accepted direction; contracts, runtimes and creative demonstrations are planned and unimplemented.

## Context

The critical vision update makes novice users working through external coding agents the primary audience. Animated educational explainers are an early flagship outcome, with synchronized Studio manual editing. Agents need typed creative operations that produce editable projects, not only flattened exports. Manim Community and Motion Canvas offer specialized animation workflows but introduce separate runtimes and potentially competing scene/project semantics.

## Decision

Rust owns the only project/timeline, native scene graph, layout and animation evaluation. After the reliable CLI/timeline/render foundation and live Studio synchronization, prioritize native composition, professional typography/vector graphics, keyframes, explanatory components, narration synchronization, scene previews/corrections and Demo A. Continue ordinary editing development without making complete traditional-editor coverage a prerequisite.

Add a declarative, versioned `SceneSpec` with stable scene/node IDs, tagged native nodes, typed properties, rational timeline spans, asset/font provenance, layout constraints, keyframes and narration cue references. Semantic operations are convenience expansions into ordinary editable low-level commands. Dry-run returns the expansion, IDs, requirements and warnings; revision checks, idempotency and atomic commit apply exactly as for existing core commands. The future Studio inspector edits those same objects. Retain operation/preset version and expansion ownership so regeneration can preserve manual overrides and surface conflicts.

Narration cues reference audio content hashes and sample ranges with measured/manual/estimated provenance and explicit uncertainty. Changing audio invalidates old alignment. Ambiguous phrases fail diagnostically. Optional forced alignment or TTS runtimes require capability/resource/license review; none is required to create scenes.

Manim Community and Motion Canvas remain optional adapters. The core owns an `ExternalRenderSpec`, editable supported parameters and source provenance. A trusted adapter creates derived worker source, renders a declared range, verifies artifacts and places them on the existing timeline. Backend caches and temporary projects are derived state. Do not execute arbitrary project-embedded Python/TypeScript. Do not claim full node editing of a baked output; declare parameter/regeneration boundaries and unsupported features.

Use static SVG as an early interchange candidate; add Lottie/dotLottie and MathJax SVG formulas only after compatibility/security prototypes. Preserve original source, editable supported subset and honest opaque fallback boundaries. No automatic downloads, backend installation or paid services occur on opening/importing a project.

Quality inspection emits structured revision-bound evidence and deterministic findings; external agents perform artistic/factual review. Proposed bounded correction defaults are three rounds plus explicit time/resource limits, with stop conditions and unresolved findings. No subjective quality score or promise of professional artistry, monetization or growth is generated by the engine.

## Evidence and alternatives

[Research and acceptance plan](../research/EXPLAINER_BACKENDS.md) records current official sources, compatibility constraints and licensing. Manim 0.22 / Python >=3.11 adds native/scientific dependencies and optional formula tooling. Motion Canvas 3.17.2 has useful named voiceover events, but documented browser export is not proof of unattended Windows integration; its integer frame-rate and automatically installed FFmpeg exporter need explicit handling. Their MIT licenses do not cover every runtime/font/asset artifact. [Manim metadata](https://github.com/ManimCommunity/manim/blob/main/pyproject.toml), [Motion Canvas time events](https://motioncanvas.io/docs/time-events/), [Motion Canvas rendering](https://motioncanvas.io/docs/rendering/), [exporter installation](https://motioncanvas.io/docs/rendering/video/).

Mandatory Manim would expedite some mathematical scenes but burdens all users and does not provide native scene editability. Mandatory Motion Canvas adds Node/browser orchestration and another authoring system. Flattened-only video generation violates the editable product requirement. An unrestricted scripting engine increases execution risk. Native scenes plus optional constrained adapters retain extensibility and minimal installation; development cost is higher, so begin with a small useful node/property set and original neural-network diagrams.

MathJax SVG is a formula interchange candidate; KaTeX's documented HTML/MathML output is a UI alternative, not a direct SVG backend. dotlottie-rs/ThorVG remain a prototype due to additional C++ build and feature-fidelity review. [MathJax Node components](https://docs.mathjax.org/en/v4.1/server/components.html), [KaTeX options](https://katex.org/docs/options), [dotlottie-rs build requirements](https://github.com/LottieFiles/dotlottie-rs/blob/main/README.md).

## Acceptance and consequences

E0 proves the single Rust project/live Studio revision path. E1 proves native editable nodes, keyframes, frame seeking, preview/export agreement and evidence extraction. E2 proves atomic semantic expansion, phrase cue changes, aspect adaptation and conflict-aware preservation of manual edits. Demo A then proves an original editable 60-second neural-network explanation with narration, nodes/connectors/labels/typography/sound, actual review and localized correction. Demo B covers supplied travel footage and editable 9:16 transitions/color/audio/captions. Demo C proves the optional Blender workflow with retained editable inputs and regenerated assets.

Each demo measures actual completion time, interventions, visual correctness, hardware consumption and rendering reliability. Independently decode exports; save editable projects and provenance. Backend absence yields explicit capability status. Do not label any stage shipped without tests and actual creative evidence. Advanced mathematical/formula/Lottie adapters may follow Demo A and must not delay native creative value.
