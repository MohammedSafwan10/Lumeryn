# ADR 0013: Native dialogs and responsive B Studio shell

Date: 2026-10-09. Status: accepted and implemented; final source/native gates recorded, physical/manual acceptance staged. Handoff: [STUDIO_REDESIGN](../design/STUDIO_REDESIGN.md).

## Context and decision

The owner selected B / Studio to replace the dense technical workspace. Preserve native Rust/egui/eframe/wgpu and the existing shared project service. Make project open, import, clip trim, preview and export clear ordinary actions; keep technical diagnostics available in an advanced area. At compact widths collapse secondary context rather than shrink important controls.

The implemented shell presents Media, central Preview, a contextual Clip inspector and a full-width timeline. Proportional clocks, icon playback/frame-step/mute controls and real monitor volume reduce technical clutter; preview gain never changes the project or exported audio. The timeline retains selection, ruler seek, right-edge trim and functional zoom/Fit, with a current-selection cursor indicator instead of unsupported tools. Its canvas adapts to remaining panel height so video and linked source audio remain in view. Compact widths move the inspector to a scrollable Clip window. History, actual settings, activity and diagnostics remain accessible in an advanced egui_dock window. Main-layout presets from the earlier technical shell are superseded by this composition and Reset view.

Use **rfd 0.17.2**, target-Windows Studio dependency with `default-features = false`. Official release notes identify MSRV1.88, compatible with Lumeryn's Rust1.97.1. Its MIT license permits commercial use while requiring the copyright/permission notice; original Lumeryn code remains proprietary. Archive the upstream license in distribution notices and rerun the complete locked dependency check after root integration. [Official release](https://github.com/PolyMeilex/rfd/releases/tag/0.17.2), [pinned manifest](https://raw.githubusercontent.com/PolyMeilex/rfd/0.17.2/Cargo.toml), [MIT license](https://raw.githubusercontent.com/PolyMeilex/rfd/0.17.2/LICENSE).

The Windows backend uses native Common Item Dialogs. Its async picker schedules synchronous dialog work on a background thread and initializes/uninitializes a COM apartment there. Studio uses synchronous `FileDialog` on one dedicated worker thread with a one-result bounded channel, giving the UI asynchronous behavior; `AsyncFileDialog` is an alternative when awaited in a background runtime. One active picker, project epochs and result-triggered repaint prevent UI blocking and stale-result edits. Create/open/import/export selection is implemented. Explicit parent-window ownership is supported by rfd but is not currently wired into Studio; focus/modality remains a manual acceptance item. Manual paths and drag/drop provide fallback without adding Linux GTK/XDG/Wayland stacks to this Windows dependency. [Pinned Windows implementation](https://raw.githubusercontent.com/PolyMeilex/rfd/0.17.2/src/backend/win_cid/file_dialog.rs), [COM lifetime implementation](https://raw.githubusercontent.com/PolyMeilex/rfd/0.17.2/src/backend/win_cid/utils.rs), [FileDialog API](https://docs.rs/rfd/0.17.2/rfd/struct.FileDialog.html).

Synchronous `FileDialog::pick_file`/`save_file` return `Option<PathBuf>`; the Windows implementation converts errors to None, so application copy must not claim that it can distinguish every cancellation from every native failure. An empty result performs no mutation and clears the picker state. The save dialog returns a path and may append an extension; independently validate the output extension/path and retain core no-clobber behavior even when the OS dialog suggests overwrite. Picker filters aid selection, not media/schema security validation. [Pinned return types and Windows extension behavior](https://docs.rs/rfd/0.17.2/rfd/struct.FileDialog.html).

## Alternatives and boundaries

Manual path entry stays available as a fallback but is not the primary beginner flow. A custom egui filesystem browser would add navigation/accessibility maintenance; native dialogs on the UI thread would freeze update work; embedding a browser contradicts the selected native architecture. rfd adds only presentation-side dialog selection. No engine window dependency, shell execution, second writer, schema change or embedded agent is introduced.

Thumbnail/waveform extraction runs in a bounded disposable presentation worker keyed by source identity and project epoch. The implemented memory cache covers the first 128 imported assets: one 192×108 representative source thumbnail each, and at most 1,024 peaks from actual 8kHz mono PCM where source audio exists. Eight-slot job/result queues and bounded UI texture-upload polling keep decoding out of painting. Tiles repeat the representative image rather than claiming temporal thumbnail sequences. The subdued filled audio silhouette samples visible source-time peaks and normalizes display height only. Loading/missing/extraction-error states remain explicit. Persistent smart caching, proxy generation and independent audio tracks remain staged. Service writes retain revision checks; exports retain immutable committed snapshots and cancellation. No schema/core rewrite or fabricated waveform/asset data is introduced.
