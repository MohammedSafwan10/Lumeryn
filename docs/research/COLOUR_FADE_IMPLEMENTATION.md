# Colour and fade implementation

2026-10-12: isolated reference module `visual_effects.rs`; no new dependency. ADR0028 defines appearance/timing/licensing. Root owns graph/service/CLI/Studio integration; this report deliberately separates helper implementation from shipped features.

`VisualEffects` has strict version 1 fields `exposure_millistops` (-2000..2000), `contrast_basis_points` and `saturation_basis_points` (0..20000, neutral10000), `temperature_basis_points` (-10000..10000), and `FadeEnvelope { in_frames, out_frames }`. No opacity duplication: static opacity stays in `VisualTransform`. Default is identity/reset. Preset enum Neutral/WarmStory/CoolClarity/SoftMono expands to ordinary numbers; intensity0..10000 interpolates around neutral, allowing subsequent manual edits.

`validate(duration_frames)` admits nonempty bounded duration and nonoverlapping fades. `lower_filters(rate,duration_frames)` returns `None` for identity and an internally generated straight-alpha encoded-SDR LUT/matrix/native-alpha-fade chain otherwise. Call after spatial transform while PTS is still clip-local, before the timeline offset. Do not feed timeline-global PTS. Native alpha-only fades preserve RGB; alpha retains intrinsic PNG/glyph/static-transform opacity and multiplies the envelope once. Rational seconds have FFmpeg microsecond adapter precision; evaluate at actual output timestamps.

`FadeEnvelope::audio_gain(rate,at_frame,duration_frames,absolute_sample)` returns canonical48k gain, explicitly zero outside the half-open clip. Use after source selection/gain in the shared mixer, using absolute project sample coordinates. `lower_audio_filters` emits native afade with exact absolute-derived local start/sample counts and linear curve; decoded sample test compares the helper per sample. Separate visual and audio properties are required. Integer source/timeline boundaries and local time conversions must be retained by speed/transition integration.

Current official documentation/maintenance sources and alternatives are recorded in ADR0028. This bounded reference uses existing FFmpeg mature Windows tooling, with no new runtime or mandatory GPU capability. Runtime cost includes format conversion, LUT and matrix processing and output buffers; avoid treating this as a fast GPU implementation. No independent decoder or worker per effect is introduced. Final encoding remains the existing discovered encoder/software fallback path.
