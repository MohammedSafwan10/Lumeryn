# Measured performance expansion

Date: 2026-10-12. Status: isolated cache implementation and tests written; root compilation, matched measurement and product integration pending. No new benchmark or shipped performance feature has been executed by this assignment. Root owns graph integration and serialized Cargo builds. No additional target directory, downloaded asset, renderer dependency or source-media mutation is required.

## Actual starting point

`scene_text::SceneRenderer` lays out and rasterizes a complete static document into a fresh straight-alpha RGBA allocation on every `render` call. Parley/Swash reuse layout/scaler contexts, but the completed scene surface is not cached. The maintained typography experiment reports UHD p50/p95 25.103/25.364 ms and portrait 29.134/29.972 ms, excluding decoding/compositing/encoding/upload. These are earlier executed measurements in [TYPOGRAPHY_IMPLEMENTATION](TYPOGRAPHY_IMPLEMENTATION.md), not a new V7 benchmark. Repeating that work every output frame already exceeds a 60 FPS frame budget.

Native preview already has an eight-command bounded queue, one-to-three decoded-frame slots, generation guards and off-UI-thread plan/decode work. Studio's presentation cache covers up to 128 source thumbnails and bounded waveform peaks; it is not a final-resolution editable-scene cache. The compositor admits three total visual placements and two active videos/one PNG. Keep those limits until actual total-cost measurements justify expansion.

## Smallest useful implementation

Wrap the existing renderer in a headless, process-local `StaticSceneCache`, owned by a render/preview worker. Initial policy: at most 64 MiB of retained pixel buffers and 16 entries, least-recently-used eviction, no disk writes. A UHD RGBA buffer is 33,177,600 bytes; two such retained entries fit in 64 MiB, before metadata/font/glyph/decoder costs. This is a retained-cache bound, **not** a process memory guarantee: outstanding `Arc` users survive eviction, and a cold miss still allocates its output. Keep caller queues bounded and measure peak process memory.

Recommended interface: `render_cached(&mut self, document: &SceneDocument, width: u32, height: u32) -> Result<SceneRaster, SceneError>`. `SceneRaster` carries `Arc<[u8]>`, dimensions, a cache key and hit/miss information. Validate documents/output bounds on every call, including hits. Checked `width * height * 4` establishes the expected length. Errors are never cached. An entry above the configured cache budget can render without retention; the renderer's existing output bounds still apply. Cache policy zero disables retention for matched measurements.

Key the **validated** ordered document plus pinned font SHA256/face, requested physical output width/height, and an explicit raster/alpha/colour-policy version. Use existing SHA256 and deterministic struct serialization with a domain prefix; no new dependency. Node order must remain significant. Stable UUIDs may remain in the initial key: changing IDs can conservatively miss but cannot reuse wrong pixels. Do not use only a project revision, source path, filename or preview dimensions. Keep revision/generation on frame delivery so an old job cannot display after an edit. Changes to fill, geometry, text, font, alignment, canvas or output dimensions naturally invalidate the key.

Reuse applies only to static scene pixels. A downstream whole-surface transform may reuse them if its documented semantics preserve the layout. Animated node appearance/geometry must evaluate the document first and obtains a different key; an LRU alone cannot turn an animated scene into a static one. Never stretch a preview cache entry into final UHD output. This optimization does not establish multilingual support, 60 FPS playback or larger-layer capability.

## Acceptance and measurement plan

Use the same reviewed font and typography fixture, then an original editable multi-node fixture at 1280x720, 1920x1080, 3840x2160 and 2160x3840. Once root authorizes compilation, use its one shared target directory and release profile. Record one cold call and at least 20 repeated warm calls with cache disabled/enabled. Timing includes validation, serialization/key hashing, lookup and raster work; separate render-only measurements are diagnostic. Record p50/p95, actual pixel SHA256, cache hits/misses/evictions/retained bytes, build/tool/font versions and observed peak working set. Compare matched pixels, not only timing. Do not predeclare a speedup.

Tests must establish same-request shared-buffer reuse; byte equality with uncached rendering; misses for every appearance/font/dimension/policy change; malformed-document rejection even after a valid hit; deterministic eviction; zero/undersized budget behavior; old `Arc` validity after eviction; overflow/output bounds; missing-font/glyph errors; and revision/generation rejection at the integrated delivery boundary. Native seek/edit/reopen and decoded UHD/portrait export must demonstrate use of the same validated renderer. If hashing/lookup does not improve matched repeated requests or memory regresses beyond the admitted budget, retain the baseline and revise the policy.

Owned implementation: `crates/lumeryn-core/src/scene_cache.rs`, with six focused correctness tests and one ignored experiment in `tests/scene_cache.rs`. The key policy/domain is an internal compile-time constant; callers cannot switch colour behavior by relabelling a policy. Font bytes are verified by the owned renderer constructor before use. `Vec<u8>` to `Arc<[u8]>` conversion can temporarily add a surface-sized allocation on a cold miss; retained accounting does not hide that peak. The cache does not itself add a cross-worker scheduler, scene persistence or revision delivery. Root must register the module and run locked focused tests/strict Clippy before any success claim.

Coordinated measurement command: `cargo test --locked --release -p lumeryn-core --test scene_cache static_cache_matched_full_call_benchmark -- --ignored --exact --nocapture`. Root supplies the shared `CARGO_TARGET_DIR`. The emitted JSON reports cold/p50/p95, identical actual RGBA/font hashes and cache counts; pixel verification hashing occurs outside timed intervals. Peak working set remains explicitly unknown until separately sampled. The experiment uses no file output, external process or extra target directory. Typography's earlier measurements remain the only executed performance evidence at the time of writing.

## Separate, later disk and scheduling work

Persistent caching should be opt-in until its actual read/hash/decode cost beats rasterization and source-integrity semantics are reviewed. It needs an application-owned cache directory, explicit byte quota, checksum/length/version validation on reads, create-new temporary publication on the same filesystem, cancellation cleanup, sole-writer service ownership and recovery tests. [Rust's rename documentation](https://doc.rust-lang.org/std/fs/fn.rename.html) describes platform/filesystem-dependent behavior; rename alone is not a durability or hostile-path guarantee. No cleanup may traverse source/project paths or symlink/reparse targets. Cache files remain disposable derivatives, not editable scene truth.

Origin-based long seeks, hardware decode/texture interop, proxies and larger layer counts have distinct bottlenecks. Measure decode/startup/seek/layout/raster/composite/upload/encode separately, retain unknown GPU telemetry, and prioritize interactive preview over optional background work. No backend replacement or unsafe/SIMD shortcut follows from the static-title measurement.

Build storage is a different issue from runtime rendering. [Cargo profiles](https://doc.rust-lang.org/cargo/reference/profiles.html) document additional incremental artifacts and configurable debug information. Multiple separate target trees duplicate dependency artifacts. Root coordinates one warm target, serialized builds and reduced debug/incremental policy; a profile change may require an initial rebuild. These choices reduce development storage, not source-media size or demonstrated export latency.

Official technical context: [Parley](https://docs.rs/parley/latest/parley/) supplies reusable layout/font contexts; it does not define Lumeryn's completed-surface cache. No new dependency or licensing obligation is added by this proposal; the existing pinned font and renderer notices remain required.
