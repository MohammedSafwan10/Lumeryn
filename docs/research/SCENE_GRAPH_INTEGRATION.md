# Static editable scene integration contract

Date:2026-10-12. Proposed patch contract following V2/schema4 acceptance. No new commands or stored scenes are implemented by this document. Builds remain serialized by root through the shared target.

Implementation checkpoint: root assigned the graph patch after this proposal. `Project.scenes` and `Project.scene_placements`, seven scene edits, schema5 admission/history migration and focused test sources are now implemented but await root's serialized compile/gates. Native/backend acceptance remains pending. The exact names below supersede earlier `scene_clips` proposal spelling. Root selected built-in reviewed-font bytes rather than mutable catalogue loading for initial admission; `scene_text::audited_font` and `validate_audited_documents` verify exact identity and layout at graph validation. Backend chooses a reviewed PNG adapter/lease rather than the optional rawvideo experiment below; source-race/lifetime/complete-output tests remain mandatory.

## Smallest safe persisted slice

Do not overload `VisualClip.media_id` with a fake font/image/media identifier. The current VisualClip assumes a verified video/PNG stream in model validation, source verification, thumbnails, usage accounting and audio planning. Changing it into optional media without a discriminated source would create invalid combinations.

Recommend schema5 **separate first-class scene objects and placements**, merging into the same VisualPlan as other visual placements. This preserves all existing media APIs and migration IDs:

```rust
Project {
    // serde default + skip when empty; disallowed under schema<5
    scenes: Vec<SceneAsset>,
    scene_placements: Vec<ScenePlacement>,
}
SceneAsset { id: Uuid, name: String, document: SceneDocument }
ScenePlacement {
    id: Uuid, scene_id: Uuid, track_id: Uuid,
    at_frame: u64, duration_frames: u64,
}
```

SceneDocument/SceneNode/content/font models are already strict and headless in `scene_text`. Initial scene canvas equals project canvas; all object position/style lives in logical project pixels. Initial scene placements occupy full canvas and are silent. Restrict scene-placement crop/rotation/opacity/placement overrides until those combinations have actual output goldens; node position/fill alpha already provides useful titles/shapes without another transform policy. A future explicit schema can unify media/scene sources if it earns its migration cost.

Admission retains **three total visual placements**, at most two active moving videos and **one active PNG-or-scene raster**. Same-track overlap includes primary/video/image/scene holds. Scene spans are half-open, checked endpoints and project frames. Duration is the max endpoint including scene clips; scene-only projects therefore have a valid picture duration and generated silence. No invented source FPS or source audio.

Bound8scene assets,64nodes each,4096bytes per text, and existing frame/canvas/render limits. Every scene/node/clip/track/project ID participates in graph-global uniqueness. Validate nonnil IDs, dangling scene/track refs, duplicate names policy, node geometry/text/font refs and existing settings refs. Scene clips may use existing overlay track IDs; initial primary track reserved for current primary clips. Deleting a referenced scene fails; delete clips and scene together in one validated batch. Rename affects display only.

Keep V2/schema4 semantics stable once verified. Schema5 migration upgrades every historical snapshot while preserving graph IDs, revisions, undo targets and command/receipt bytes; both new collections default empty. Opening remains readonly; no automatic owner-project upgrade. New scene commands require current schema. Default schema field omission alone cannot authorize old-reader writes.

## Exact typed editing contract

Start with complete-document replacement to avoid a sprawling property-patch framework:

```text
CreateScene {id,name,document}
SetScene {scene_id,document}            // exact replacement, preserve existing node IDs
RenameScene {scene_id,name}
DeleteScene {scene_id}                 // referenced => explicit error
AddScenePlacement {id,scene_id,track_id,at_frame,duration_frames}
MoveScenePlacement {clip_id,track_id,at_frame}
SetSceneRange {clip_id,at_frame,duration_frames}
DeleteScenePlacement {clip_id}
```

SetScene validates final document before transaction. Adding/removing nodes uses an ordinary replacement generated by either client; do not regenerate unrelated UUIDs. Editing a shared scene intentionally updates all its placements; `scene duplicate` returns a new scene/node-ID mapping when independent editing is wanted. One gesture is one replacement/batch/undo step. Missing properties cannot silently reset a partial patch because this API explicitly replaces the full document.

Initial implementation omits RenameScene and scene duplicate; names are set on CreateScene, and duplicates require explicit new scene/node IDs in a batch. Existing per-operation validation means scene canvas conversion is explicitly rejected while scenes exist; remove/recreate deliberately rather than advertising an unimplemented simultaneous-canvas-relayout operation.

Proposed CLI:

```text
scene list/inspect/check --scene-id ...
scene create --name ... --document <bounded JSON file> --id ...
scene set --scene-id ... --document <bounded JSON file>
scene rename/delete --scene-id ...
timeline scene add --scene-id ... --track-id ... --at-frame ... --duration-frames ...
timeline scene move/range/delete --clip-id ...
```

All edits reuse explicit `--project`, inspected `--expected-revision`, optional idempotency and batch dry-run. Discovery exposes schema5, implemented primitive/font IDs/bounds and unsupported animation/fallback capabilities. Inspect includes editable document; diagnostics must never dump private title text. `scene check` reports scene/node IDs, bounds/overflow/missingfont with the standard error envelope. Catalogue fonts are discovered through existing assets APIs; add a bounded `scene fonts` view only if useful, without a duplicate registry.

## Trusted pinned font loading

Use the existing shared `Catalog` from `core/library.rs`, not project-supplied filesystem paths or system fonts. Initial renderer admits only reviewed regular Inter4.1 catalogue ID `inter.v4.1.inter-opsz-wght`, SHA256 `29160a80ff49ddcab2c97711247e08b1fab27a484a329ce8b813d820dc559031`, face0. Catalogue entry must have Font kind, exact reviewed SHA/size and OFL notice. Resolve through `Catalog::verified_path`, bounded-read bytes, then SceneRenderer's hash check. A mutable manifest declaring a novel font hash is not an admission allowlist.

The core resolver can expose `VerifiedSceneFonts::load(catalog)->Result<...>` and `renderer_for(&FontRef)`. Resolve once per generation/job outside UI and writer locks; retain bytes for its immutable snapshot. Missing installation/hash/face/glyph errors must reach both clients before commit/render instead of silently falling back. Project stores identity, not machine path. Reopen remains portable with the reviewed pack installed. Additional audited fallback fonts need an explicit registry/corpus; existing Inter alone is not multilingual complete.

Pure `SceneDocument::validate` does not shape text. Before a service write, stage a bounded font/layout check on the proposed document, bound to incoming expected revision and input bytes. The final transaction repeats pure admission; a concurrently changed project still conflicts. As bytes are already immutable/verified, do not do font disk scans inside the Store writer lock. Document size limit should use the existing IPC/batch bound plus a stricter scene JSON limit (e.g.256KiB), rejecting huge inputs before parsing/layout.

## Shared preparation and render lifetime

VisualPlan needs an explicit source discriminator at the preparation boundary. A practical API is `PictureInput::Media {path,digest,...} | Scene {scene_id,document,font_identity,...}` rather than a dummy path. Its duration/order/active-frame admission remains pure; scene text layout/raster happens later for the actual requested output.

`PreparedVisualProgram` owns both the current `VisualProgram` and its prepared scene resources. Suggested shape:

```rust
PreparedVisualProgram {
    program: VisualProgram,
    rasters: Arc<SceneRasterLease>,
}
prepare_visual(plan, output_width, output_height, fonts, cancel)
    -> Result<PreparedVisualProgram>
```

Prepare static title once for a generation/job, at requested final physical scene dimensions. Keep project-pixel wrapping; scale glyphs directly, never upscale720p text forUHD. Existing SceneRenderer rejects nonmatching aspect; add an explicit fitted-viewport API (single uniform scale + offset/clip) before arbitrary aspect-ratio exports. Standard16:9/9:16 fixtures work now; rounding an arbitrary fitted canvas must not stretch text or cause mysterious aspect errors.

For the initial subprocess adapter, store one **raw RGBA frame** in a private owned temp resource, not a public PNG path. This avoids a PNG encoder dependency or extra FFmpeg process. Rawvideo requires explicit pixel format, dimensions and rate; replay a seekable one-frame input with stream-loop, then bound it with existing trim. [Official rawvideo format docs](https://ffmpeg.org/ffmpeg-formats.html#rawvideo), [official FFmpeg input loop option](https://ffmpeg.org/ffmpeg.html). This input mode requires an actual short parity test before use; a documentation recipe is not execution evidence. Named pipes would require extra feeding/lifetime machinery and are unnecessary for one static frame.

No project edit stores the temp path. Create-new file/unique directory, exact byte length/hash and trusted local-file protocol. Retain its lease until the decoder/render child exits or is killed/reaped. Preview workers must clone that lease across task spawning; export cancellation joins/kills the worker before releasing it. Do not create a TempDir inside VisualPlan::from_project and return dangling filenames. Child can reopen the read-only file on Windows; avoid NamedTempFile delete-sharing assumptions without tests. RAII cleans only the directory owned by that job after its child lifetime; never recursively sweep project/cache roots.

Use `PictureSource::SceneRaster` or a distinct prepared image mode in generated FFmpeg input args. It has no source-media proof; hash the generated bytes against the lease, while external media retain existing pre/post proofs. ActivePNG-or-scene bounds remain explicit. The same prepared lowering runs preview and final output; no Studio shader/private glyph rendering. AudioPlan counts scene endpoints and produces silence, never treats scene ID as media.

## Cache and native specialist boundary

Start with a bounded ephemeral scene raster cache, **64MiB** budget. Cache key covers canonical full SceneDocument bytes/node order, exact font SHA/face, layout/raster engine versions, output viewport, alpha/colour policy and schema. Revision alone is insufficient. Retain immutable bytes/files through leases; evict only unleased entries. Pending/error is explicit; interrupted/partial file is never a cache hit. Project switch/revision/canvas/font/policy edits must cancel stale preparation and invalidate by actual content. Persistent global caches/proxies remain Area6's measured slice; no unbounded disk accumulation.

Native Text/Shapes drawer inserts real scenes through the service. Right Inspector edits text/font/size/line-height/alignment/fill/position in one replacement on acceptance; metadata/per-nodeUUID advanced. Timeline scene holds render the same leased prepared thumbnail; node selection maps stableID to property edits. A private draft is bound to project/revision/epoch and uses the shared scene renderer off the UI thread. Escape/focus/stale revision cancels; explicit apply commits once. No advertised preview handles/keyframes until those interactions work.

Static title raster measured ~25msUHD; cache reuse is required before60FPS claims. This slice needs no one-subprocess-per-frame path. Animation later supplies exact-time property evaluation and may reuse static rasters for transform-only movement; font/text/layout changes invalidate. Do not add keyframes to the first persisted scene contract merely because the isolated evaluator exists.
