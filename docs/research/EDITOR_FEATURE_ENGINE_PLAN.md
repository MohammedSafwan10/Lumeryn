# Editor feature engine audit and implementation order

Date: 2026-10-09. Source inspected: local checkpoint `d6e5940`. Scope: Rust engine, service, CLI, preview/export and migration requirements. This is a source audit and implementation proposal; no code, dependencies or running application were changed and no new tests or benchmarks were executed. The checkpoint's recorded 62 distinct tests are existing baseline evidence, not acceptance of the missing editor features below. The overall Clipchamp product inventory and Studio UX report are separate deliverables; this document maps the requested editing families to the actual Lumeryn engine.

## Actual source boundary

Inspected `crates/lumeryn-core/src/{model,time,storage,media,render,lib}.rs`, `crates/lumeryn-service/src/{protocol,client,server}.rs`, `crates/lumeryn-cli/src/main.rs`, `crates/lumeryn-preview/src/{plan,decode,audio,lib}.rs`, existing ADR 0005 and the architecture/progress records. There is no separate core `evaluate.rs`: baseline layout evaluation is embedded in `render.rs` and repeated by preview `plan.rs` and audio/video workers. The core exports only error, media, model, render, storage and time modules.

`Project` schema 1 contains dimensions, rational frame rate, one `video_track_id`, media references and clips. A `Clip` contains only IDs, project position, source-in and duration in frames. `Edit` has exactly `Import`, `AddClip`, `TrimClip`. `Project::validate_clip` requires matching verified CFR video, rejects audio-only placement and every other track ID. Its range validation permits gap/overlap positions; renderer and preview reject such layouts later. The renderer accepts 1..64 contiguous clips beginning at zero, square-pixel SDR and zero-origin audio/video. It preserves source references/digests, renders project dimensions, generates silence when embedded audio is absent, exports native MPEG-4 Part 2/AAC MP4 and verifies full decoding before publishing to a new path.

The service serializes typed commands through one writer with revisions, dry runs, atomic batches and retry receipts. History stores commands and snapshots at each monotonically increasing revision. Receipt replay retries a committed request; it is not timeline replay, undo or redo. The existing storage migration updates storage/index infrastructure, not an editor graph conversion. `checked_project` accepts only the current exact schema, so graph migration needs explicit versioned decoding.

## Feature status at this checkpoint

“Done” means implemented within the stated narrow scope. “Partial” means useful groundwork exists but the full requested editing behavior is missing. “Missing” means no authoritative command/model and no end-to-end preview/export implementation. A visible lane, FFmpeg filter or history record alone does not establish a working feature.

| Feature | Status | Actual behavior / absent engineering |
|---|---|---|
| Create 16:9, 9:16, 1:1 projects | Done, creation only | CLI landscape 1920×1080, portrait 1080×1920 and square 1080×1080 defaults; explicit even dimensions and rational FPS. |
| Change existing aspect/canvas; 4:3/other presets | Missing | No canvas-settings edit command, content reposition policy or preset registry. Custom dimensions on creation are not an existing-project edit. |
| Import, placement, source trim | Done, baseline | Typed commands, IDs, transactional updates; one CFR video lane. Source trim leaves `at_frame` unchanged and does not ripple later clips. |
| Split | Missing | Needs one atomic two-clip operation, exact source range partition and stable/new ID contract. |
| Delete / remove gap / ripple delete | Missing | No deletion command or downstream-shift policy. Empty-project rendering also needs an explicit behavior. |
| Duplicate | Partial foundation | Existing AddClip can manually create another source range under a new ID; no duplicate command, inherited settings or placement policy. |
| Move / reorder / insert / ripple trim | Missing | Position is set only on AddClip. No existing-clip position update, ordered-selection or ripple semantics. |
| Copy, cut, paste and multi-selection edits | Missing | No versioned clipboard payload or authoritative paste batch; cut is not an OS clipboard action alone. |
| Undo / redo | Partial foundation | Durable snapshots/history exist; no undo/redo request, stack policy, conflict handling or branch behavior. |
| Gaps / blank background | Partial, not playable | Graph accepts positions, but preview/export reject any gap; no explicit project duration/background source. |
| Multiple video tracks, layers, picture-in-picture | Missing | One track ID; no layer ordering, opacity, visibility, transforms or compositor. |
| Independent audio clips/tracks | Partial media foundation | Audio-only files can have imported metadata; timeline placement rejects them. Source-audio waveform lane is linked display, not a mixer. |
| Project/per-clip gain, mute, fades | Missing | Real monitor gain/mute exists only in PreviewPlayer and is intentionally absent from project/export. |
| Detach audio, relink, audio/video groups | Missing | No independent clip kind, group IDs or suppression of the original embedded contribution. |
| Mix, ducking, channel mapping, noise/loudness processing | Missing | Embedded source sound or generated silence is normalized to stereo 48kHz and concatenated; no overlapping mixer. |
| Crop / fill / explicit fit | Partial default fit | Fixed aspect-preserving scale and pad is implemented. No editable crop rectangle or fit/fill choice. |
| Rotate / flip / position / scale / opacity | Missing | No semantic transform object or preview/export compositor; imported orientation metadata is not an editing command. |
| Exposure / contrast / saturation / temperature / transparency / blend mode / reset | Missing | No persisted numeric controls, blend enum or reset-to-default command. Transparency is composited clip alpha, not monitor volume; exposure/temperature require a specified SDR color transform. |
| Filters, color correction, LUTs, visual effects | Missing | No typed effect registry, parameters, color policy or output verification. SDR baseline is not color management. |
| Transitions and video/audio fades | Missing | Hard concat exists; no overlap/handle duration model or crossfade evaluator. |
| Rational speed, slow motion, reverse | Missing | Source and timeline durations are identical frame counts. FPS compatibility is not speed control. |
| Freeze frame / still-image placement | Missing | Seek/paused preview does not create an editable freeze clip. No still clip duration/model. |
| Editable titles, captions, animated text | Missing | UI typography and imported raster footage are not semantic project text. ADR 0005 is research, not an implemented renderer. |
| Plain/animated title preset gallery | Missing | No semantic preset catalog, native text layers, timed animation curves or parameter-editable instantiated title. Raster stock footage cannot substitute. |
| Caption import/edit/export and automatic transcription | Missing | No timed cue graph, SRT/VTT transport, font policy or transcription storage/model. |
| Project-resolution MP4 export | Done, baseline | Output dimensions equal project; native MPEG-4/AAC preset only, with post-encode verification. |
| Export-only 480p/720p/1080p/4K selection | Missing | Preview quality changes decoding/upload bounds only. No typed render-resolution override. Project custom dimensions can be large; no 4K throughput acceptance. |
| 4K “Upmarket” upscaling control | Missing | Needs an explicit upscale export transform/preset and truthful source/output resolution; increased pixel dimensions do not establish recovered detail or AI super-resolution. |
| H.264/HEVC/AV1, GIF/WebM, audio-only export | Missing | No preset negotiation, compatible muxer matrix or lossless audio-only path. Installed encoders are not integrated presets. |
| Frame-rate conversion / VFR / HDR | Missing | CFR matching and explicit baseline rejections remain; no optical-flow or managed HDR pipeline. |
| Autosave/live synchronization | Done, scoped | Edits persist transactionally; Studio/CLI share service events with bounded replay and snapshot resync. This does not provide cloud collaboration. |
| Numeric video/audio fade-in/out seconds | Missing | No clip fade fields, checked seconds-to-frame/sample conversion or shared envelope evaluation; transitions and monitor gain do not provide this. |
| Media rename / delete context actions | Missing | Imported paths/media IDs exist, but no display-name edit or remove-reference command. Deleting a project reference must not delete source bytes; in-use policy must be explicit. |
| Record screen+camera / camera / screen / audio | Missing | No capture permissions/device selection, native worker, recording job state, safe output/import transaction or cancellation. |
| Text-to-speech voices and generated audio | Missing | No TTS request/model/voice registry, reviewed voice license or resulting project asset; transcription is a different capability. |

## Official facilities versus Lumeryn behavior

FFmpeg has relevant primitives: `trim`/`atrim`, `scale`/`pad`/`crop`, `rotate`/`transpose`/flips, `overlay`, `eq`/color filters, `xfade`, `volume`/`afade`/`amix`/`acrossfade`, `setpts`/`atempo`, and subtitle rendering. `xfade` requires compatible CFR inputs, dimensions, format, rate and time base. `atempo` supports 0.5..100; factors above 2 can skip samples, so chained factors can be preferable. `subtitles` needs a libass-enabled build. These are backend options, not completed Lumeryn features. Probe the installed build and translate validated typed operations; never expose raw filter strings as project commands. [Official filters](https://ffmpeg.org/ffmpeg-filters.html), [codec availability/configuration](https://ffmpeg.org/ffmpeg-codecs.html).

The current egui-wgpu callback API offers prepare/finish-prepare/paint stages and resources on the existing renderer device. It enables a future composited preview surface but does not supply timeline, captions or export semantics. Keep the Rust evaluator window-independent; reuse the current device and bounded frame/scene queues. The exact 0.36.2 integration and wgpu 30.0.1 remain the baseline; a shader optimization requires measured parity rather than a second GPU context. [Callback contract](https://docs.rs/egui-wgpu/0.36.2/egui_wgpu/trait.CallbackTrait.html), [wgpu 30.0.1](https://docs.rs/wgpu/30.0.1/wgpu/).

Parley supplies rich text layout, not a finished creative scene/export engine. Follow ADR 0005: bounded semantic text/cue objects, resolved font identity, shared glyph layout and a CPU reference renderer before optional GPU acceleration. Compare cosmic-text/Vello under the same multilingual goldens. Keep egui labels separate from creative text fidelity. [Parley upstream](https://github.com/linebender/parley), [ADR 0005](../adr/0005-typography-audio.md).

CPAL is the current native device boundary, not a multitrack DSP engine. Keep decoded/mixed buffers prepared off its callback. A shared Rust sample-frame mixer should feed both playback and lossless export. Rubato remains an optional measured resampling candidate; its documented startup-delay/short-buffer fixes reinforce impulse and short-clip acceptance. Resampling alone does not establish pitch-preserving speed changes. [CPAL 0.18.2](https://docs.rs/cpal/0.18.2/cpal/), [Rubato current documentation](https://docs.rs/rubato/latest/rubato/).

## Incremental dependency order

Each stage is a complete typed CLI/service operation, Studio interaction, persistence round trip and preview/export acceptance slice. Add controls only when the underlying capability is available. This order is a recommendation for the lead's task board, not a claim that implementation has begun.

Canonical delivery order and task IDs are CC00–14 in [Clipchamp feature inventory](../roadmap/CLIPCHAMP_FEATURE_INVENTORY.md). The local E0–10 sequence below remains an engineering recommendation supporting those tasks; the common evaluator is core-first work within CC02/CC04. The canonical inventory supersedes these local labels for scheduling and progress tracking.

E2's export resolution can ship before multitrack. Simple gain/mute on embedded audio can also ship before E4 if stored and evaluated in the common graph; it must not reuse monitor-only volume. Text/captions and layer compositor can progress together after E3/E5; native explainers stay an early goal rather than waiting for every effect in E9. No MLT/backend replacement, cloud dependency or embedded agent is required by this order.

Owner's additional screenshots identify numeric fade durations, named color controls/reset, transparency/blend mode, title galleries, recording modes/TTS and media context actions. Their availability in another editor does not supply Lumeryn semantics. Implement media display-name/reference removal with E1/E2; reset removes only the selected typed property/effect family under one revision. Initially support `Normal` compositing only and reject unimplemented blend modes; expand after known-color/alpha goldens. Define exposure/temperature units, transfer space and parameter range rather than copying display slider values into arbitrary filters. Fade fields use explicit seconds or rational time on input and checked frame/sample boundaries in the evaluator; validate fade sums against short clip duration. Title presets instantiate editable text/style/animation objects with stable IDs and resolved fonts, not pre-rendered animations. E2/E9's 4K upscale option must name the actual algorithm and show source resolution separately; optional AI upscale remains model/resource/license gated.

Recording can run independently of the later compositor once service jobs and asset import are reliable. Screen+camera composition may first import separate synchronized persistent sources; presenting a combined recorded layer requires E3/E5 or an explicit baked-media choice. Native Windows Graphics Capture uses system selection/capture facilities; camera capture has capability/device/privacy prerequisites, and microphone PCM uses a device capture stream. Keep API/FFI isolated in an optional Windows adapter, perform processing off the UI thread, request required user/device permissions and implement stop/cancel/failure states. Write a new temporary recording, finalize and fully verify it, then atomically register a persistent media reference. Do not import an incomplete file or discard a recording silently on UI close. [Windows screen capture](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture), [MediaCapture camera](https://learn.microsoft.com/en-us/uwp/api/Windows.Media.Capture.MediaCapture), [WASAPI capture stream](https://learn.microsoft.com/en-us/windows/win32/coreaudio/capturing-a-stream). These official platform facilities have not been prototyped in Lumeryn and UWP examples do not prove direct compatibility with the current native Win32 shell.

Local TTS/transcription stay optional model services and produce ordinary persistent audio/cue assets through the same command graph. Separate engine/model/voice licenses, supported languages, storage and download consent, hardware scheduling and speaker/style restrictions; no mandatory cloud service, paid voice or automatic customer-data upload. Generated audio still needs timing, format, cache/source identity and cancel/retry acceptance. TTS generation is not microphone recording, and speech recognition is not caption shaping.

## Time, graph and command contracts

Use integer project frames and checked rational source mapping. All ranges are half-open. Split at project frame `p` preserves the original left ID, creates a supplied right ID, rejects endpoints, and partitions source ranges without duplication or omission. Ripple operations state their affected track/group scope and checked offset; a trim is not silently converted into a ripple edit. Reorder supplies stable IDs plus a clear insertion destination; incidental Vec order must not redefine layer order or playback.

Audio placement needs a sample-frame domain at an explicit project sample rate, plus a defined mapping from project frames. Compute neighboring range boundaries from absolute rational positions; repeatedly rounding each clip duration can accumulate drift. Preserve stream origin, channel layout, encoder priming and resampler delay. Detach creates an audio clip referring to the same immutable source and suppresses that video's embedded contribution; group/link behavior must be explicit on trim, move, speed and delete. The waveform cache is disposable presentation data, never the authoritative audio signal.

Transforms need a documented coordinate space, origin/pivot, crop order, alpha convention and composition order. Filters need a supported color space/range and deterministic order. Transition semantics specify whether they shorten composition or consume available source handles; an FFmpeg default cannot choose project meaning. A freeze is a media/frame reference with its own output duration, not a huge repeated-frame allocation.

Clipboard payloads describe validated clips/assets/settings with size limits and schema version; paste remaps IDs and destinations inside one service transaction. Cross-project paste resolves/validates source references and optional copying policy without modifying originals. Undo is a new command/revision restoring supported prior semantics, not overwriting history or decrementing revision. Define whether undo targets the latest global edit or a named operation under concurrency; initially reject stale expected revisions rather than silently undo another client's intervening work. New edits after undo invalidate that redo branch explicitly.

## Backward-compatible migration

Keep graph version, SQLite storage version and IPC/API version separate. Schema 1's strict `deny_unknown_fields` and exact-schema validation mean additive project properties are not readable by old binaries. Introduce explicit V1 DTO decoding and an audited conversion to the new internal graph; never deserialize an old snapshot as a permissive latest struct and invent lost settings.

Before graph migration, create a consistent service backup to a new path. Preserve project/media/clip/track IDs, source digests, revision and relative references. Convert the single lane into an ordered video track with default identity transforms, speed 1/1 and existing embedded-audio behavior; new fields must reproduce old rendered output. Any newly explicit audio track IDs/defaults must be deterministic or stored once. Verify old gaps/overlaps without silently dropping or rearranging clips: their original baseline export was unsupported and migration should report their layout.

Historical snapshots, backup reference rebasing, integrity checks and undo all need version-aware graph readers. Preserve immutable original history records or explicitly store versioned migrated representations with an audit record; do not corrupt command/receipt canonicalization. Existing idempotency receipts must retain their original replay semantics. In one transaction, update current snapshot/version, indexes and migration record only after all validation passes; failure leaves the old project intact. Unsupported newer schemas/protocols fail clearly. Restart an incompatible project service during the explicit upgrade rather than allowing old/new writers or guessed wire fields.

Required migration fixtures: genuine schema-1 database with history/receipts and portable references, prior storage-version-0 database, missing legacy digest, noncontiguous layout, and corrupt/newer snapshot. Migration twice is idempotent; dry-run changes nothing; backup reopens; source bytes and hashes stay unchanged. New capability reports must distinguish engine/preview/export/Studio support per operation, rather than one “effects supported” flag.

## Preview/export parity and measured acceptance

One evaluator produces source frame/sample requests, ordered layers, transforms, audio envelopes and output duration for the immutable revision. Preview quality may reduce spatial resolution; it cannot change time mapping, crop, effect order, color meaning or project audio gain. Export resolution is an explicit render option over that same graph. Every adapter returns unsupported-feature diagnostics before misleading partial output. Metadata-only native scenes require no window to inspect/render.

Use lossless FFV1/PNG/raw RGBA and PCM WAV references for pixel/sample assertions; lossy MP4 acceptance uses full decode plus documented pixel/audio tolerances rather than byte equality. Test selected frames immediately before/at/after each boundary, complete frame/sample counts, source hashes before/after, cancellation/timeouts, bounded admission and service responsiveness during export. Include two client revision conflicts and idempotent retry for each new command family.

Record actual warm/cold load and seek p50/p95, continuous 720p/1080p decode/compose throughput, export wall time, UI CPU/latency, idle CPU, host/GPU memory, audio underruns and ten-minute scheduled/physical A/V drift separately. Use generated/trusted fixtures: single clip, ten cuts, deliberate gaps, four visible layers, long audio and caption-heavy scenes. Name machine, build profile, dependency/tool versions and source hashes. Existing decode-worker load 70–80ms and seek 126–136ms (historical worker measurements; native cold first frame differs), plus paused CPU evidence, are comparison baselines only. The final native application first-frame measurement was approximately 797.73ms. Multi-layer budgets cannot be inferred from single-layer playback. Admit fewer jobs/degrade preview quality explicitly if measured budgets are exceeded; do not drop final export semantics.

No implementation performance claim is added by this research. Proxies, content-addressed caches, indices, hardware interoperability and native FFI require separate measured experiments and invalidate affected scene/audio/source dependencies. Benchmarks operate on Lumeryn's actual command/render paths; standalone FFmpeg speed is not application speed.

## Licensing and supply-chain boundary

Keep Lumeryn proprietary. egui/wgpu and Parley main code are permissively licensed; preserve MIT/Apache notices and review locked dependencies. Parley emoji/test assets have separate terms. CPAL uses Apache-2.0; Rubato's candidate graph is reviewed under ADR 0005. Fonts, caption sources, LUTs, templates and stock assets need independent redistribution rights. [wgpu metadata](https://docs.rs/crate/wgpu/30.0.1), [Parley license exceptions](https://github.com/linebender/parley), [CPAL metadata](https://docs.rs/crate/cpal/0.18.2).

FFmpeg licensing depends on the exact configuration and optional libraries; the installed GPL executable is user-supplied and is not bundled. Enabling x264 or other GPL components is not a permissive dependency selection. Codec patent obligations remain separate. libass itself uses ISC, while its integration/fonts still need review. Rubber Band offers GPL or paid commercial licensing; do not add it or incur a license charge automatically for speed processing. Prefer an inspected permitted implementation and measured quality before selecting an alternative. [FFmpeg legal](https://ffmpeg.org/legal.html), [libass license](https://github.com/libass/libass/blob/master/COPYING), [Rubber Band upstream](https://breakfastquay.com/rubberband/).

This plan installs nothing, publishes nothing, changes no important requirements and leaves optional models/renderers outside the minimal install. Root owns the overall inventory, ADR decisions, task board and implementation authorization following the inventory review.
