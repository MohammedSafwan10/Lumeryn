# Editable explainers and optional animation backends

Research date: 2026-10-09. This is an architectural proposal, not implemented functionality. No Manim, Motion Canvas, dotLottie or formula runtime was installed or benchmarked. The critical product vision update prioritizes novice users working through external agents, while retaining professional manual editing of the same project.

## Recommendation and priority

Keep Rust project state, timeline evaluation, scene objects and creative commands authoritative. After the reliable timeline/render/CLI foundation and live Studio synchronization, prioritize native composition, text/vector graphics, keyframes, explanatory components, narration cues, scene previews/correction and Demo A. Do not wait for every traditional editor feature. External agents own research, script/storyboard creation and artistic review; Lumeryn exposes capabilities and evidence without embedding a competing agent or MCP layer.

Native scenes give editable nodes and shared preview/export evaluation without another mandatory runtime. Manim is a later optional mathematical-animation worker; Motion Canvas is a later optional TypeScript animation worker. SVG is the first static interchange candidate; Lottie/dotLottie and advanced formula rendering follow explicit compatibility prototypes. Existing ADRs 0003–0005 govern preview, resources, typography and audio; ADR 0008 governs truthful capability discovery and optional installation.

Motion Canvas supports image-sequence export and separate preview/render settings. Its documented project frame rate is a whole integer, so fractional Lumeryn rates require explicit sample mapping and verification. Changing resolution does not automatically adapt object layout. Its FFmpeg exporter automatically installs FFmpeg; use image output and Lumeryn's reviewed encoder first, rather than silently acquiring another binary. Browser canvas color spaces and encoded output require a measured color/alpha fixture, not an HDR claim. [Rendering documentation](https://motioncanvas.io/docs/rendering/), [FFmpeg exporter](https://motioncanvas.io/docs/rendering/video/).

The current dotlottie-rs README warns its crates.io alpha is stale; it recommends a pinned Git release, requires Rust >=1.85 and builds vendored ThorVG with a C++ toolchain/clang/libclang. Windows MSVC targets are documented. This adds native build and ABI/supply-chain costs even though the top-level API is Rust. Do not add an unpinned Git dependency. Upstream cross-platform consistency claims require Lumeryn's own Windows corpus before acceptance. [Official build requirements](https://github.com/LottieFiles/dotlottie-rs/blob/main/README.md).

MathJax v4 Node conversion is asynchronous, can load extensions/fonts, and can start workers requiring shutdown. Use an explicit local component/font set, no remote loader, bounded formula length/expansion, and complete worker termination. Standalone SVG must include needed paths/styles; mathematical glyph paths alone do not preserve text selection, so retain the source expression and accessibility text. KaTeX has maxSize/maxExpand/trust options; keep untrusted input constrained rather than accepting arbitrary URLs or HTML. ## Proprietary distribution and execution boundary

MIT/Apache code can be used commercially subject to notices and applicable obligations; Lumeryn stays proprietary. Audit exact transitive artifacts, fonts, example assets, templates and output asset rights before bundling. Cairo offers LGPL-2.1 or MPL-1.1; choose and document a compliant distribution path if bundled. PyAV wraps linked FFmpeg libraries, so Manim's MIT label does not make a wheel's codec build unrestricted. Review each PyAV wheel's FFmpeg build and source/notices. Motion Canvas's automatic FFmpeg acquisition likewise needs a separate binary review. User-installed optional tools avoid making their runtime part of the minimal package, but do not erase obligations when redistributed. [Cairo licensing](https://www.cairographics.org/), [PyAV upstream](https://github.com/PyAV-Org/PyAV), [existing media decision](../adr/0002-media-backend.md).

Project JSON must not carry Python/TypeScript/shell code that is executed on opening. A trusted versioned adapter expands validated data into controlled source in a private work directory and invokes explicit arguments. Advanced arbitrary user scripts require a separate trusted workflow. Subprocesses are not sandboxes: limit privileges, assets, environment, execution time, child processes, output size and resources; block network through an actual enforcement mechanism before claiming isolation. Never resolve project credentials into workers. Reject archive traversal/absolute paths, excessive uncompressed ZIP sizes, external resource fetches and output paths escaping the worker directory. Decode/probe outputs before accepting them atomically.

## Proposed typed scene contract

These are design shapes, not shipped CLI schema. Publish precise JSON Schema only when implemented, with migrations and rejection of unknown required features.

- `SceneSpec`: schema version, stable scene ID, project timeline span, canvas/aspect, theme/brand-kit references, asset hashes/provenance, stable node IDs, constraints, animations and narration cue references. Tagged node kinds begin with group/text/shape/path/connector/asset; diagram/chart/formula/external render follow gated support. No arbitrary executable expression field.
- `SemanticOperation`: versioned operation/preset plus explicit parameters (reveal graph, comparison, timeline, coordinated typography, object highlight, phrase sync, aspect adaptation). Dry-run expands to typed low-level object/property/keyframe commands and returns created/affected IDs, warnings and requirements. One existing revision-checked, idempotent transaction commits the expansion; invalid expansion commits nothing.
- `Animation`: target ID, supported typed property, rational-time keyframes, easing enum or validated bounded curve, interpolation rules and explicit units. Endpoints, conflicts and zero-duration cases are validated. Randomized layouts require a recorded seed. Native evaluation at a requested frame is independent of render history.
- `LayoutConstraint`: anchors, bounds, gap/alignment, text wrapping, safe area and priority. Unsatisfiable constraints yield diagnostics, not silently clipped content. Aspect adaptation creates reviewable edits on existing IDs; it does not just crop the landscape image.
- `NarrationCue`: audio asset/content hash, stable phrase/token reference, sample-index range, alignment method (manual/measured/estimated), confidence or unknown, and offset. Changed narration invalidates dependent alignment; duplicated or missing phrases need structured ambiguity diagnostics. TTS estimates are not measured forced alignment. Optional aligner models are separately licensed/probed.
- `ExternalRenderSpec`: adapter/backend version, retained editable parameters/source spec, asset hashes, seed, exact project time mapping and declared opaque boundaries. Worker request adds frame range, resolution, color/alpha, resource plan and cancellation. Result includes verified frame count/timing, output hashes, diagnostics and provenance. Cache keys cover all inputs and font/backend versions.

Native semantic expansion produces real editable objects; retain the versioned source spec plus expansion mapping. Manual property overrides remain authoritative and visible. Regenerating a component replaces only its owned, unchanged properties; conflicting overrides require a dry-run conflict result, not silent overwrite. Derived backend source/cache never becomes another authoritative project. A baked Manim/Motion Canvas asset is parameter-editable/regenerable only to the extent of the adapter; never describe its pixels as individually editable native nodes.

## Creative QA contract and bounded review

Plan scene-range preview, frame extraction and contact sheets tied to the exact project revision/render hash. A `QualityReport` contains rule/version, severity, object IDs, time range, evidence image/audio references and measured values or explicit unknown. Deterministic checks cover missing assets, decode failures, unintended gaps/black frames, text bounds/safe areas, overlap exceptions, cue/caption timing and audio peaks. Intentional black, overlap and silence need declared exceptions. Peak values do not prove narration intelligibility; expose listening segments and optional alignment/ASR evidence with uncertainty. Motion continuity and factual correctness require external review.

An external agent may inspect rendered frames/clips, propose localized edits and repeat. Proposed default budget is at most three correction rounds, explicit wall-time/resource budgets and a maximum affected scene count. Stop when required checks pass and the reviewer accepts, when a capability/input blocks progress, when a round produces no useful improvement, or when the budget is exhausted. Return outstanding findings. Do not manufacture artistic scores or infer professional quality from technical pass/fail.

## Phased creative acceptance

All entries are TODO and require actual evidence; no demo is claimed complete.

| Stage | Dependencies / scope | Required acceptance |
|---|---|---|
| E0 | Reliable timeline/render/CLI; authenticated live Studio sync | CLI-created edits and Studio manual edits use one revision stream, survive reopen and conflict/reconnect tests. Existing core gates remain mandatory. |
| E1 | E0; native composition, text/vector and keyframes | A short original node/connector/label animation is editable by stable ID in CLI and Studio. Seek/random frame evaluation agrees with export. Preview/contact sheet exposes exact timing, fonts and overflow diagnostics; no optional backend required. |
| E2 | E1; explanatory components and narration cues | Graph reveal and phrase sync expand atomically to editable nodes/keyframes; change one label, voiceover or aspect and correct only the affected scene. Missing/ambiguous cue handling is tested. Manual overrides survive component regeneration. |
| Demo A | E2; audio mixer, scene review/export | Original 60-second neural-network explanation: verified script claims, synchronized narration, animated nodes/lines/labels/typography and sound. Save editable project plus provenance, actual preview/contact sheets and independently decoded export. Agent performs bounded review and one targeted correction; user can edit afterward. |
| Demo B | Media trim/selection plus transitions/color/audio/captions | Supplied authorized travel clips become an editable 9:16 Reel with useful shots, smooth transitions, color treatment, music/narration/captions. Review actual images/audio, safe areas and gaps; source files remain immutable. This does not delay E1/E2. |
| Demo C | Native composition + separately proven optional Blender adapter | Editable mechanical/product scene spec and retained Blender inputs, verified 3D render with narration/labels on the same Lumeryn timeline. Modify a parameter and regenerate only that worker asset/affected range. Absence of Blender is an explicit unavailable capability. |
| Optional adapters | E1–E2; separately reviewed runtimes | Manim mathematical fixture, Motion Canvas voiceover fixture and SVG/Lottie/formula corpus pass Windows frame-count, rational-time mapping, alpha/color, missing-font, unsupported-feature, cancellation and no-network tests. No mandatory dependency added for Demo A. |

For each experiment record host/OS/GPU/driver, tool/dependency hashes, resolution/rate/frame count, cold/warm startup, elapsed time, manual interventions, peak RAM, measured/unknown VRAM, disk/cache size, failure/cancellation recovery and repeatability. Compare identical native/adapter scenes where possible. Set preview and final-render budgets from measured results on a modest Windows host; do not invent performance thresholds or report an unrun benchmark.
