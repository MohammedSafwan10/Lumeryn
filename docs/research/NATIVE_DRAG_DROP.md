# Native media placement and timeline dragging

Research date: 2026-10-10. Baseline inspected: `a2cf04e`, before this implementation. This records recommendations and acceptance criteria; it does not establish implemented or physically tested functionality.

The owner requests media-card placement, clip shuffling and useful audio dragging in the existing approved native editor. Preserve the Rust graph/service, source immutability, revision checks, durable undo and current native rendering. No new GUI toolkit, browser editor or third-party drag library is required.

## What the interaction must achieve

Microsoft documents importing into My media, then dragging an asset into the bottom timeline or using its add button. This supports retaining Lumeryn's add button as an accessible alternative while adding a visible drop target and immediate placement feedback. [Clipchamp editing workflow](https://support.microsoft.com/en-us/clipchamp/how-to-edit-a-video-in-clipchamp).

Clipchamp documents separate layer placement, seek/zoom controls and a horizontal scrollbar. For Lumeryn's current contiguous visual graph, the truthful first contract is insertion/reordering between visual clips, with a snapped boundary marker and ripple displacement. Free placement, gaps and overlapping visual layers need their own evaluator support. The timeline feedback must say what release will do, without implying unsupported layer behavior. [Clipchamp timeline](https://support.microsoft.com/en-au/clipchamp/how-to-work-with-the-timeline-in-clipchamp).

Clipchamp's gap tools can pack adjacent assets and snap them together. This is useful reference behavior, but Lumeryn should not silently repair pre-existing unsupported gaps during an ordinary drag. Reject an unsupported graph with an actionable error; require a separate explicit gap-removal operation. [Clipchamp gap removal](https://support.microsoft.com/en-us/clipchamp/how-to-remove-gaps-on-the-timeline).

Dragging the current linked Source audio display cannot honestly create independent music editing. Microsoft describes detaching audio into a separate clip that can be moved independently, and muting the original video contribution affects export. Genuine Lumeryn audio placement needs persisted independent audio ranges, shared preview/export evaluation, and atomic detach that suppresses the embedded contribution. A second decorative waveform would double sound or misrepresent capability. [Clipchamp audio separation](https://support.microsoft.com/en-gb/clipchamp/how-to-mute-separate-and-delete-audio-from-video). The existing composition research specifies timing/migration requirements in [COMPOSITION_FOUNDATION.md](COMPOSITION_FOUNDATION.md).

## Native API selection and maintenance

Keep the already pinned egui/eframe 0.36.2 implementation. Its built-in `DragAndDrop` plugin stores typed `Any + Send + Sync` payloads, cancels on Escape at beginning of a pass and clears unconsumed payload on mouse release at end of a pass. The payload remains readable during the release pass. No Windows-only OLE plumbing is needed for dragging within the editor. [DragAndDrop documentation](https://docs.rs/egui/latest/egui/struct.DragAndDrop.html). Pinned registry source was inspected directly because some version-specific documentation requests were unavailable.

Use custom-painted cards/clips with `Sense::click_and_drag()` and `Response::dnd_set_drag_payload` at drag start. `dnd_hover_payload`/`dnd_release_payload` use `contains_pointer`, since normal `hovered` is false during another widget's drag. Release extraction consumes the payload. Low-level `DragAndDrop::payload` and `take_payload` permit one lane handler after clip interactions have been registered; use explicit clipped-lane geometry and primary-button release. [Pinned response source](https://github.com/emilk/egui/blob/0.36.2/crates/egui/src/response.rs).

Avoid replacing the captured payload each frame. The higher-level `Ui::dnd_drag_source` reissues its supplied payload while the widget remains dragged; passing today's revision into it could refresh an obsolete gesture. Its automatic moved-widget painting is unnecessary for Lumeryn's existing custom timeline. Use a small inert preview on a tooltip layer that cannot intercept input. The checked local 0.36.2 `ui.rs` implements this distinction. [Ui documentation](https://docs.rs/egui/0.36.2/egui/struct.Ui.html).

The dependency's local package manifest declares `MIT OR Apache-2.0`, Rust 1.95, and version 0.36.2. This uses the existing reviewed dependency rather than changing Lumeryn's proprietary licensing or adding a runtime. Upstream describes eframe Windows/native wgpu support, and release history shows ongoing fixes. These establish platform support/maintenance, not a guarantee that every pointer/device workflow is correct. [Official project](https://github.com/emilk/egui), [official release history](https://github.com/emilk/egui/releases).

## Gesture contract

Recommended payload consists of immutable project UUID, Studio epoch, committed revision, and a tagged source: imported-media UUID or timeline-clip UUID. Capture it only after drag threshold is crossed. A media card's click still selects; double-click/add still appends through the same placement command. Unsupported audio/image kinds should explain their supported route or missing foundation, never masquerade as video.

Hover only computes presentation state: lane, insertion boundary, snapped frame and ghost. Keep SQLite writes, media probing, hash checks, FFmpeg launch and project mutation out of pointer movement. On primary release in an accepted clipped target, consume once, recheck epoch/project/revision/connection/pending-edit state, and submit one authoritative service transaction. Use the gesture's expected revision; never retry stale input automatically against a changed graph. If an external agent edits while dragging, cancel with a short visible explanation. Project switching, disconnected service or opening a modal cancels the gesture.

One gesture must be one undo step. A core `InsertClip` operation is preferable to reproducing ripple semantics in Studio; an existing atomic append-plus-reorder batch is acceptable if validated centrally and advertised consistently by CLI/schema. Reordering preserves clip IDs/source ranges. Dropping a clip back into its current slot should create no needless revision/history item. Never reinterpret an existing trim gesture as a reorder.

Allocate disjoint body/trim hit rectangles. The body excludes the right-edge handle before intersecting with the real viewport; a partially visible clip's clipped right border is not necessarily its actual trim edge. For very narrow clips, prioritize a usable selection/body gesture and expose trimming in Inspector rather than two overlapping controls. Keep ruler seek, track headers and scrollbar outside drop targets. Receiving widgets painted later must not steal pointer capture from clip bodies.

Escape clears the egui payload at pass start. Preserve that cancellation until release: do not reseed from a still-held mouse. Releasing outside the target produces no edit. Losing window focus cancels. Pointer `hover_pos()` becomes absent on `PointerGone`, while `interact_pos()` intentionally retains the position of a release/touch interaction; use the latter on the release frame without treating missing hover as an automatic rejection of valid touch input. A secondary-button release cannot commit a primary-button gesture, even though the generic response helper observes any-button release.

## Coordinates, scrolling and bounds

Use the actual scrolled content origin, pixels per project frame and clipped lane rectangle; test under fit, zoom, fractional rates and horizontal scroll. Visual insertion can use the nearest slot boundary with a deterministic tie rule, rather than treating the dragged source as free placement. During reorder, omit the dragged clip from candidate slots and calculate prospective packed positions. This prevents a self-target and misleading marker offsets when moving across clips of unequal duration.

Egui 0.36.2 `ScrollSource.drag` is a `DragScroll` enum, defaulting to `OnTouch`. Set `Never` for editable timeline content to keep touch dragging from also panning; preserve wheel and scrollbar navigation. `ScrollAreaOutput` exposes actual ID/state/content size/inner rectangle. Bounded edge autoscroll can update its stored horizontal offset, clamped to the content extent, and request repaint while a valid drag is held. The next frame must recompute the marker from the new origin. [Pinned ScrollArea API](https://docs.rs/egui/0.36.2/egui/containers/scroll_area/struct.ScrollArea.html).

Recommended edge band is measured in logical points, with capped points/second speed and capped frame delta; these are tunable interaction defaults, not benchmark results. Disable fit changes while a gesture is active or freeze gesture geometry; never let automatic fit after provisional insertion move its target. Salt/reset scroll state by project epoch so another project's offset cannot corrupt first placement. Do not allocate or sort all clips on each pointer movement without measuring the 10,000-clip path; a cached ordered slot list can be rebuilt on revision changes.

## Verification required before completion

Use multi-frame `egui::RawInput` events against the real card and timeline widget handlers, not tests that merely call a placement helper. First settle layout to obtain real rectangles. Feed pointer movement, primary press, threshold-crossing movement, target movement and release in separate passes. Assert no semantic action during hover; exactly one action on accepted release; no second action on the next pass. Exercise source handler before target in the same frame, matching the editor's panel order.

Test empty visual timeline placement, beginning/middle/end insertion, unequal-duration reorder in both directions, same-slot no-op, clipped-body dragging, actual trim edge dragging, ruler seek and scrollbar coexistence. Include zoom/scroll target conversion, compact layout, offscreen source after drag begins, edge autoscroll, and large metadata/visible-paint behavior. Assert boundary marker/ghost are painted in the hover frame.

Inject Escape while primary remains down and continue movement before releasing. Inject project/revision/epoch change mid-gesture, focus loss, outside release, secondary release and unsupported source/lane. These must never persist an unintended edit. If the underlying service rejects a stale revision after the UI check, show the error without local optimistic graph mutation.

At service level, use generated immutable footage: insertion/reorder result, dry-run, conflict, transaction rollback, idempotent replay, Undo/Redo, reopen, two-client live event and decoded output ordering. A pointer-generated action should be submitted through the same service path used by ordinary Studio. Native real-window evidence must include the new gesture path; launching a window or invoking reorder directly establishes neither drag input nor drop feedback. Physical mouse/touch/high-DPI interactions remain separately identified unless executed.

Independent audio acceptance requires imported audio-only placement, move/trim/delete, gain/mute/fades, overlapping contributions with a documented mix policy, and source bounds. Validate decoded output samples and marker alignment at rational project rates, seek parity, frame duration and UHD output, plus no double audio after detach. Audio metadata currently lacks an authoritative sample duration, so source-range correctness and historical graph migration are implementation prerequisites, not optional polish.

No new dependency, asset download, external upload, backend replacement or unsafe code is proposed by this research. Performance measurements and executed acceptance belong in the milestone evidence after implementation.
