# Visual composition: next executable foundations

Research date: 2026-10-10. Status: proposed delivery design, not implemented capability. This report owns only visual layers, gaps, image holds, crop, rotate and overlays; typography/effects/time changes have companion reports. No dependency, production graph, source asset or owner project was changed by this research.

## Concrete starting point

The authoritative graph is schema2 in `crates/lumeryn-core/src/model.rs`: one `video_track_id`, a list of `Clip` values, and independent audio. A Clip has integer project position/duration and integer source-frame offset. Source video must have the project's exact constant rational rate. Graph validation permits up to10000 video clips; actual preview/export accept only1..64 contiguous clips starting at zero. These are different limits and capabilities must expose them separately.

`render.rs::export_with_progress` sorts by position, rejects gaps/overlaps, trims/scales/pads sources and concatenates. `lumeryn-preview/src/plan.rs::Plan::build` independently enforces the same contiguous restriction, while `decode.rs::video` starts a controlled FFmpeg decoder per sequential segment. Preview defaults to1280×720, three buffered frames and eight queued commands. `apps/lumeryn-studio/src/gpu.rs` uploads completed RGBA to eframe's existing wgpu device using Rgba8Unorm; this presents decoded frames and does not implement a shared multi-layer compositor.

`audio_plan.rs` already supplies canonical48k audio to preview/export. Visual duration is the maximum video endpoint, independent sound cannot extend beyond it, and at most64 combined contributions are admitted. Additional video layers can multiply embedded-audio contributions: count them explicitly and preserve this bound until measured changes justify an increase. Layer visibility must not silently imply audio mute.

Native `timeline.rs` has single video and linked-source-audio rows plus independent Audio1. Video drops select insertion boundaries and ripple the contiguous sequence; audio bodies use grabbed-offset movement. Preserve these existing operations instead of changing their meaning when composition arrives. PNG thumbnails and stock provenance exist, but a still image is currently not an editable timed visual object. A repeated frame count is not a valid way to assign a photograph its display duration.

## Smallest coherent implementation

Build a window-independent, checked **VisualPlan** inside the existing core before editing persisted topology. It maps a committed revision/schema/colour policy and exact rational project time to a deterministic list of active visual sources, transformations, order and background. Integer timeline frames are editing boundaries; export-rate conversion and animation must preserve fractional evaluation times. Preview, still-frame inspection and final export consume this same plan and colour/alpha policy. Reuse existing source verification, job cancellation, RenderOptions, encoder selection, canonical AudioPlan and create-new output publication.

First implement an offgraph fixture evaluator and generated FFmpeg reference lowering. This proves bounded multiple sources, precise gaps/holds and crop/rotate/alpha with real decoded frames before a new graph can accept those edits. For the first persisted slice, one shared CPU filter lowering is preferable to independent Rust CPU, WGSL and export implementations arriving simultaneously. Keep the current sequential fast path for schema1/2 after parity tests; do not introduce another mandatory runtime or crate merely to name an abstraction.

Reference filter generation takes typed numeric parameters and generated labels. Paths remain separate arguments. User-provided FFmpeg expressions, URLs, scripts and shaders are not editing commands. The reference must explicitly set interval endpoints, source PTS mapping, alpha policy and output colour conversion. If installed FFmpeg cannot initialize that reference, return a prerequisite failure during preflight and reject unsupported composition edits; do not save an apparently editable project whose preview/export silently omits objects.

A CPU reference is not automatically the final fastest backend. The same VisualPlan can later feed a wgpu offscreen renderer available to headless export as well as Studio. That requires software/headless adapter handling, render/readback measurements, actual texture interop evidence and reference pixel agreement. Do not put renderer semantics in `apps/lumeryn-studio/src/gpu.rs` or require a window in core.

## Proposed exact semantics

1. **Topology/order:** stable visual-track UUIDs with explicit bottom-to-top order. Track names and hidden/locked UI state are separate from order. A track contains nonoverlapping half-open clip intervals in the first slice; overlap on the same track fails until typed transitions exist. Different tracks may overlap. Track reorder is one revision-checked edit. Deleting a referenced/nonempty track requires an explicit atomic batch, never hidden deletion.
2. **Time:** clip visible for `at_frame <= frame < at_frame+duration_frames` with checked endpoints. Gaps reveal lower layers; a gap in all layers reveals project background, default opaque black. Total visual duration is maximum visual endpoint, including image holds; trailing empty duration needs a later explicit project-duration operation. Keep exact project FPS and current matching-CFR video requirement initially. Images hold immutable content for explicit integer duration and have no source FPS. Still-only timelines lock rate when a hold exists. No floating millisecond accumulation.
3. **Source types:** distinguish VideoRange, ImageHold and later generated scene nodes through typed discriminants. Video retains source frame proofs; image uses content digest, verified dimensions/format/colour/alpha and decoded size. Images never fake video frame counts or canonical audio. Unsupported animation/multi-image PNG, SVG scripting, external references and unreviewed image colour profiles fail explicitly.
4. **Geometry:** store crop in unrotated source coordinates, before fit/scale. Use integer pixels for first static crop, with `left/top/right/bottom` strict bounds and nonempty result; do not silently coerce zero crop. Position/pivot/size belong to project-canvas units, not preview pixels. Use checked fixed precision for persisted coordinates, positive dimensions and bounded angles; flips are explicit booleans rather than negative scale. Define clockwise rotation in the canvas's downwards-Y coordinate system. Order is source orientation normalization → crop → fit/scale → flip/rotate about pivot → position → clip to canvas. Quarter turns arrive before arbitrary-angle rotation unless the arbitrary case passes the same tests.
5. **Fit:** `contain` preserves aspect ratio and exposes underlying background; `cover` is a centered source crop unless a focal point is explicitly supplied. Crop mode offers an actual source crop frame, while transform mode resizes/moves the visual result. Project canvas/export dimension changes apply one output transform after project-space evaluation. They must not multiply each object's persisted coordinates or flatten its editable state.
6. **Alpha/colour:** contract version belongs in plan/cache identity. The practical initial FFmpeg picture compositor must specify its actual SDR RGB/YUV formats, input transfer/range/matrix assumptions, sampling, opacity and straight/premultiplied overlay behavior before shipping. One generated lowering produces completed composites for both preview and export; Studio does not blend independently. An experimental ordinary overlay graph is not linear-light colour management. The preferred professional target is linear-light BT.709-primary RGB with premultiplied alpha for sampling/compositing and explicit output conversion to SDR BT.709, subject to actual adapter feasibility. Source-over is `Cout=Cs+Cd*(1-As)` and `Aout=As+Ad*(1-As)` for premultiplied channels. Apply opacity to both premultiplied colour and alpha; with straight channels apply it once to alpha. Never gamma-transform alpha or multiply it twice. A later GPU or CPU fallback reproduces the stored contract; a different pixel algorithm needs a new policy version and explicit appearance conversion, not a silent upgrade. HDR/wide-gamut inputs remain unsupported. Unknown source colour requires a visible, persisted assumption or explicit conversion choice; no silent universal BT.709 inference. Current Video metadata stores only color_transfer, not primaries/matrix/range/orientation/alpha. Verified import metadata must be extended and old unknowns handled explicitly before claiming those conversions.
7. **Audio:** preserve existing canonical48k positions and independent gain/mute. Every video contributes its source audio under existing policy, even when visually occluded; mute is explicit. Image holds contribute silence. Gaps do not shorten sound. Shortening final visual duration that strands audio fails with the existing explicit remedy. Later detach/link/fade/speed edits need their own typed contract, not UI-derived implicit mixing.
8. **Transactions:** add/move visual clip takes destination track, exact position and optional explicit ripple policy. Existing InsertClip/ReorderClip retain single-primary contiguous semantics and reject incompatible use. SetVisualRange/SetTransform updates validate their final state atomically. Gesture preview is transient and commits once on accepted primary release; Escape/focus loss/overlay/revision or epoch change discards it.

## Migration and command safety

Graph schema3 is proposed, not a request to increment SCHEMA_VERSION today. Replace ad hoc `schema_version == SCHEMA_VERSION` assumptions with explicit version-aware shape validation before introducing3: current audio validation otherwise treats schema2 as neither historical nor current. Preserve schema1/2 readers and migration-only edit guards. Existing v1→v2 migration assumes all historical graphs are schema1; adding3 requires composed migration functions rather than skipping2.

Back up through the live-WAL-safe service first. In a bounded transaction transform current and all history snapshots with stable track/object IDs, retain editing revision and raw command/receipt bytes, preserve undo/redo equivalence, verify current snapshot equals last history, rebuild indexes and notify a same-revision schema event. Generate topology IDs collision-free across **all** historic video, audio, project and media IDs. Unknown/mixed/corrupt historical schemas roll back; no partial forward write. Old binaries reject3 and restore uses the consistent backup. Opening a project does not migrate it automatically.

CLI schema/capabilities/preflight must advertise typed tracks, image-hold placement, move/range/transform operations, defaults, limits, prerequisites and unsupported colour/source/effect policies. Agents inspect actual source metadata and plan dry-runs before committing. Inspector, direct handles, presets and CLI batches call the same service edits with expected revision/idempotency. Template insertion later expands to stable editable IDs in one atomic batch; it does not store a black-box prerender as a claim of editability.

## Native interaction and organisation

Preserve the two rails, expandable drawers, Inter typography and mint selected state. Left My media/Library shows verified video/image assets with drag and keyboard Add alternatives. Add offers an explicit target layer and duration for images. Right Clip drawer has concise Crop & fit and Transform sections plus numeric precise controls and Reset. Reuse current icons/tooltips instead of flooding controls with technical labels.

Timeline adds vertically scrollable named visual rows; render only visible rows/clip intervals, with spatial/range indexes as measured scale requires. Media drops show a snapped insertion/placement ghost and target row. Primary video reorder remains familiar; free move/gap creation is an explicit tool/mode, not a change to existing ripple behavior. Snap to playhead and nearby clip endpoints with a pixel-space threshold translated to integer frames; allow a clear temporary modifier to bypass snapping. A selected overlay gets resize/crop/rotate handles only in its current mode, zoom-correct hit bounds and a pivot indication. Grip/body/trim hit regions remain disjoint, with accepted-only edge scrolling and a keyboard alternative. On conflict discard gesture and explain retry; never silently rebase.

## Bounds and baseline measurements

Admission must be based on active decoders, surfaces and combined audio contributions, not solely total clip count. A UHD RGBA8 surface is33177600bytes; three buffered frames are99532800bytes before decoder/filter/GPU memory. A floatRGBA UHD surface is132710400bytes. These are arithmetic budgets, not observed peaks. Multiplying the current per-source queue by every clip would be unacceptable.

Use one bounded composite-output queue, active-source decoding only, decoded still reuse and cancellation generations. Compile intervals by stable active-set boundaries; do not open10000 FFmpeg inputs or start a process for every frame. Initial accepted limits must be small and explicit (two moving layers plus a still is a useful first acceptance fixture); a larger supported cap requires measured admission, not optimistic marketing. Chunking/stitching export can follow a proven monolithic bounded slice, with exact boundary/audio continuity tests. Seek must output the exact requested composite frame and discard stale results.

Record fixture hashes/tool versions/hardware, cold/warm startup, seek p50/p95, sustained1080p30/60 and UHD export throughput, peak RAM/process counts/GPU bytes, UI CPU separately from display latency, underruns/dropped frames, cancellation responsiveness and repeated-seek cleanup. Compare plain sequence, gaps, one still, two moving layers and several overlays with concurrent import/export. Proxy resolution may fall while editing; final export always evaluates originals at final output dimensions. No zero-copy or60FPS claim without these measurements.

## Licensing and alternatives

[FFmpeg's official legal guidance](https://ffmpeg.org/legal.html) distinguishes LGPL baseline from GPL-enabled components and nonfree configurations. Installed availability is not redistribution authorization; review exact filters/libraries/encoder configuration and codec patents before packaging. Keep existing dependency notices and reviewed stock manifests; Lumeryn remains proprietary. No Clipchamp proprietary stock, icons or title designs are copied.

Retaining the existing external FFmpeg adapter avoids new FFI and duplicated decoding. libav bindings could later remove process overhead, but require evidence, ABI/tool distribution management and isolated reviewed FFI. A wgpu shared offscreen compositor is strategically coherent but must match the reference and work headlessly. MLT remains optional reference/research, not a replacement graph. Changing to a browser canvas or Studio-only painter would undermine CLI/export parity. No new backend, dependency or broad refactor is justified by this planning report alone.
