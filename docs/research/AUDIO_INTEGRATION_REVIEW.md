## Correctness boundaries reviewed

- Graph schema 2 uses a separate stable audio-track identity and independent clip IDs. Source offsets use canonical 48 kHz sample frames; timeline positions/durations retain rational project frames. Validation rejects duplicate object IDs, absent proofs, wrong tracks, nonzero origins, multichannel sources, invalid gain, source overruns and audio extending beyond the visual duration. Overlap is intentional.
- Explicit migration opens an immediate transaction, validates contiguous historical snapshots and logical undo targets, allocates one audio-track ID absent from every historical object's IDs, and upgrades all snapshots. Current revision, command text and receipt bytes are retained. Errors roll back the transaction. Legacy read/check/backup paths remain available; edits require explicit migration. Undo rejects a restored schema or audio-track identity that differs from the current graph.
- Canonical source proof decoding happens outside the project writer lock and is subject to the import-slot bound. Proof application checks media ID, project reference, size and BLAKE3 identity again inside the write transaction. Expected-revision validation still applies; receipt replay precedes expensive proof preparation. A stale proof cannot silently attach to a different reimport with the same media UUID.
- Sample counting streams PCM through a fixed-size buffer rather than retaining whole-source audio. Decode status, stderr bounds, timeout, pre/post source hashes, complete interleaved sample frames and explicit zero-origin mono/stereo eligibility are checked.
- The shared mixer computes each contribution length from absolute sample boundaries, avoiding accumulated per-clip rounding. Source counting and range evaluation use the same canonical resampling policy. Embedded historical audio alone permits silence padding; independent contributions require proven source bounds.
- Preview and export activate the same generated canonical mix when independent clips exist. Per-contribution gain/mute precedes additive mixing; normalization is disabled and final samples are clamped. Device conversion follows the canonical mix. Seek slices the evaluated mix so converter state and source ranges match sequential output. Paths remain individual process arguments, never executable filter text.
- Preview uses its existing bounded sample queue and cancellation select around the entire worker, including backpressure waits. Export retains original source hashes, full output verification, create-new publication and service-controlled background cancellation. No new renderer, dependency or unsafe code was introduced.

## Acceptance limits

The reviewed graph permits at most 64 independent clips, while the mixer permits at most 64 **combined embedded and independent contributions**. A graph may therefore be valid yet exceed preview/export's stated backend limit; those paths reject it explicitly. Do not describe the limit as 64 independent clips plus 64 embedded clips.

Studio's initial placement default requires a stored canonical sample proof. CLI Add can lazily prove an older imported source; Studio instead gives a reimport instruction for unproven sources. This is not video-audio detach. Embedded source audio remains linked and at unity gain; independent gain/mute does not mute a video's embedded stream. Audio split, duplication, clipboard, detach, fades, multiple independent lanes and audio-only export remain outside this slice.

Mix seeking evaluates earlier samples before slicing. Repeated sources use one decoder input per contribution, bounded to 64. Neither fast long-program seeking nor low decoder overhead has been established. Source pre/post hashes do not prevent a changed-and-restored file race. Physical speaker/display synchronization, device latency, high-DPI pointer usability and subjective sound quality need separate acceptance.
