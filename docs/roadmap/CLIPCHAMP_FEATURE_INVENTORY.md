# Clipchamp reference: feature inventory and Lumeryn delivery plan

Date: 2026-10-09. Scope: the owner's18screenshots, source audit at local checkpoint `d6e5940`, and current official research. This is the requested first inventory milestone; no new editor feature is claimed implemented. The owner authorizes Clipchamp-style organisation and later implementation/downloads. Keep Lumeryn branding, native Rust, local-first storage and the shared service. B remains a verified historical checkpoint; the new references refine navigation rather than replace the engine.

Status legend: **working** = scoped implemented/tested behavior; **partial** = related foundation exists but the pictured action does not; **missing** = new implementation needed; **optional** = later capability with independently verified runtime/model/provider prerequisites. Tab presence alone is not proof of its hidden options. All proposed CLI names below are design contracts, not existing commands.

## Evidence, reuse and practical boundaries

- Current62-test source/media/native evidence remains in [Studio acceptance](../testing/STUDIO_REDESIGN.md). It verifies the existing B baseline, not this backlog. Current source: core model/schema1 with Import/AddClip/TrimClip; CLI create has Landscape/Portrait/Square; native preview expansion is not full screen; waveform cache is first128assets/one representative thumbnail/max1024peaks.
- [UI/screenshot audit](../research/CLIPCHAMP_UI_REVIEW.md), [engine plan](../research/EDITOR_FEATURE_ENGINE_PLAN.md), [asset/license plan](../research/BUILTIN_ASSET_LIBRARY.md) record specialist findings/current official sources.
- [Microsoft's editing documentation](https://support.microsoft.com/en-us/clipchamp/video-editing-features) supports the reference feature families. The owner images determine the observed screen contents.
- [Microsoft's stock-audio terms](https://support.microsoft.com/en-us/clipchamp/how-to-add-stock-music-and-audio-to-videos) permit licensed resulting Clipchamp videos but prohibit taking the individual stock files into other editors. Lumeryn will use independently licensed packs/original templates; not Clipchamp media.
- Reuse FFmpeg for decode/encode/DSP facilities and existing native GUI/audio workers. A backend filter existing does not mean Lumeryn supports it. No mandatory browser/MLT/AI runtime or new low-level backend is selected by this inventory. Review exact versions/dependencies/licences and measure before implementation.

ThenCC-02, while audited library preparation runs independently. This milestone intentionally stops at the owner's requested first complete feature list, not a claim of completed editor parity.
