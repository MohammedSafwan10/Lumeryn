# Security and trust boundaries

Lumeryn is local-first and proprietary. No network control API, automatic model downloads, cloud uploads, billing or project-supplied scripts exist in the initial slice. Report findings privately to the owner; no public issue tracker has been configured.

Media, metadata, project databases and executables are untrusted. Rust uses typed commands, input bounds, parameterized SQL, schema validation, revision checks, transactional writes and argument arrays without a shell. The media adapter accepts existing canonical local files, restricts FFmpeg protocols, limits process output, applies timeouts and kills dropped workers. Exports validate temporary output before publishing without overwriting an existing file. JSON success goes to stdout, diagnostic/error JSON to stderr.

These are mitigations, not a media sandbox. Installed FFmpeg still runs with the current user's permissions and may have vulnerabilities. On2026-10-10 the owner authorized a checksum-verified external FFmpeg/ffprobe9.0.2 pair, with8.1.1 preserved for rollback. Refreshed sessions select9.0.2; already-open processes may retain8.1.1. Selected generated-media compatibility checks passed, not a security certification. See docs/research/FFMPEG_TOOL_UPDATE.md and docs/testing/FFMPEG9_COMPATIBILITY.md. Keep binaries patched; review executable provenance. Network filesystems, hostile symlink races, database tampering and compromised executable search paths are residual risks. First-slice imports now persist full BLAKE3 content hashes checked before/after probing/export. These detect ordinary source changes, including same-size replacements, but cannot prevent hostile change-and-restore races; stronger immutable snapshots and OS worker isolation remain required before untrusted-project distribution.

Future service: current-user OS permissions, explicit Windows named-pipe ACL, reject remote clients, authenticated session handshake, no unauthenticated listener; revision events and authoritative writer. Future model/adapters: checksums, pinned runtimes, limited trust, no arbitrary Python/Blender script from media or projects. Store configured credentials in OS credential storage. Never commit secrets or private customer assets.

Recovery: SQLite WAL transactions protect committed edits, and history records accompany each revision. Interrupted export never replaces final output; abandoned private scratch artifacts may require owner-directed cleanup. Keep project database and WAL together during live backup; proper SQLite backup tooling is a later task.

The implemented `project backup` uses SQLite VACUUM INTO with invariant/integrity verification and create-new publication. It preserves asset-reference meaning across directories and does not copy or delete assets. Explicit migrations retain revision history; unknown schemas are rejected without changing unrelated databases. Owner-controlled corruption repair and interrupted-process crash-injection remain later tests. Cargo-deny performs advisory/license/source/bans checks; a passing scan does not certify native binaries, models, codecs, fonts or asset redistribution.
