# Lumeryn architecture

Current work adds native left/right rails, context drawers and true same-window fullscreen over the approved B engine. A curated offline catalogue supplies stable IDs and audited metadata to CLI and Studio; hashing/decoding/import preparation run outside the UI loop. Libraries stay filesystem assets, not database blobs or a second editing graph. Library source import uses the same revision-checked service transaction. Independent audio/image placement and richer browsing follow composition slices.

Unrestricted UHD is a first-class product requirement (PRODUCT_SPEC owner addendum). Shared RenderOptions specify final resolution, 24/25/30/60 FPS, MPEG-4/H.264/H.265, quality, optional bitrate and CPU/automatic acceleration. Render uses original bytes and a final-resolution virtual project canvas, avoiding a low-resolution preview or project-size intermediate. Encoder discovery initializes the requested codec/dimensions/FPS and records hardware choice or software fallback. Revision-pinned service jobs emit real processing stages, preserve cancellation, create-new output and decoded verification. The supported graph remains contiguous single-track CFR SDR video plus embedded audio/silence; native text/vector/mask/composition parity needs tests as each family arrives. 8K/HDR/mastering remain staged. Exact-build FFmpeg/libx264/libx265 redistribution and patent obligations remain reviewed separately from installed encoder availability.

**Desktop: native Rust egui + eframe + egui_dock + egui-wgpu + wgpu/WGSL. This supersedes the earlier Tauri/Svelte/WebView architecture. See ADR 0010 and the preserved native migration requirements.**

Authoritative requirements: [PRODUCT_SPEC](docs/PRODUCT_SPEC.md). Publisher branding is NEXDARK LABS, a pending sole-proprietorship brand, not a claim of registered incorporation.

Primary users are people with little editing knowledge who brief an external agent in ordinary language. The agent directs narrative/storyboard/assets, performs edits, reviews actual output and makes bounded refinements. Lumeryn executes deterministic creative/editing operations and exposes the same editable project to professional humans in Studio. Autonomous, Review and Refine, and Professional Manual Editing are workflows over one engine. No built-in competing agent or MCP. Animated educational explainers are an early flagship capability, not an artistic-quality guarantee.

The workspace contains `lumeryn-core`, `lumeryn-cli`, `lumeryn-service`, `lumeryn-preview`, and `apps/lumeryn-studio`. The core owns validated project types, rational frame evaluation, persistence and controlled media workers. The CLI translates semantic commands and emits JSON. No UI code owns editing rules.

Studio retains the approved B media cards, readable elapsed clocks, mint controls, real thumbnails/waveforms and contextual trim Inspector within the requested native two-rail organization. Wide windows show both drawers; compact windows show the active side and allow both to collapse. The timeline shares the central stage so full-height sidebars remain stable. True OS fullscreen retains the same preview session/device and hides editing chrome. Advanced egui_dock tools contain history, activity, project details and diagnostics. Native create/open/import/export dialogs remain on a dedicated bounded worker with stale-epoch rejection. Basic clip context commands, shortcuts and canvas choices use the same service-backed Rust edits as the CLI. ADRs0014–0016 and testing/CLIPCHAMP_FOUNDATION.md record the implementation and acceptance limits.

Owner's next interface direction uses Clipchamp-style native left creation/library and right contextual-property rails with expandable drawers over the verified B engine. The18-image feature inventory and canonical CC-00–14 sequence are in docs/roadmap/CLIPCHAMP_FEATURE_INVENTORY.md; ADR0014 preserves native/local-first/proprietary constraints. New editing families need typed shared Rust semantics, CLI/schema/capability discovery and Studio controls, versioned graph/history migration where needed, and decoded preview/export parity. The proposed local asset library uses audited pack manifests/stableIDs/provenance/licences/filesystem bytes shared by both clients; asset placement is an ordinary revision-aware project edit. Libraries, recording/TTS/captions/filter/transition/speed/upscale features remain staged, not implemented by this inventory. No dependency, backend or mandatory cloud/model is introduced.

The Studio presentation cache decodes one representative 192×108 source thumbnail and an 8kHz mono PCM peak envelope with at most 1,024 bins for each of the first 128 imported assets. A bounded background worker validates source identity; UI uploads use the existing egui renderer device. Entries/results are keyed by source identity and project epoch, with explicit loading/error states. Thumbnail tiles repeat that representative image; the linked Source audio lane samples actual peaks with display-only normalization. This is ephemeral memory, not a persistent content-addressed smart cache or independent audio-track implementation. Monitor mute/volume applies preview-only gain in the native audio callback without changing project semantics, export audio or the sample clock.

Flow: CLI or Studio → versioned local IPC → shared Rust project service → typed command → validation → SQLite transaction → versioned project snapshot/history. Render reads a committed snapshot, evaluates clips in Rust and invokes an isolated media adapter. Original assets are references and remain immutable. Stable UUIDs identify project, tracks, media and clips. Timeline durations and positions are integer frames at a rational project rate; source frame ranges use an explicitly compatible source rate.

Persistence: versioned SQLite with WAL, FULL durability, foreign keys, bounded lock waits, one transaction per mutation, revision conflict checks and idempotent receipts. The first implementation uses a small JSON graph in transactional rows; later indexed tables can be migrated without changing public commands. The Windows project service owns the Store writer. CLI and Studio use current-user ACL-protected named pipes with remote-client rejection, bounded JSON messages and correlation IDs. Clients subscribe to a bounded in-memory event stream after commit; reconnect and expired cursors resynchronize from the persisted snapshot. Event cursors are transient, while editing history and revisions are durable. Studio never writes SQLite directly. Long-running renders capture an immutable revision and run outside the writer lock, with bounded admission and cancellation.

Each portable project owns `project.lumeryn`. There is no PostgreSQL, Firebase, Appwrite or mandatory cloud store. The independent global app database is staged for installed-model manifests, settings, hardware benchmark profiles and shared metadata; it never becomes necessary to reopen a project. Large media/model/cache bytes stay on disk. New project storage includes verified FTS5 metadata search; transcript indexing follows actual transcription storage. An optional local vector index remains unselected pending CLIP/corpus recall/latency/memory/Windows benchmarks. Graph schema and storage migration version are separate. Explicit transactional migration, integrity/history/index checks, and `VACUUM INTO` backups are implemented; cross-directory backups rebase relative references to the same original assets and do not copy media. See ADR 0001.

Media: user-installed FFmpeg/ffprobe via argument arrays, local files only, bounded output and timeouts. Current export supports one contiguous nonoverlapping video track with compatible CFR, SDR, square pixels, zero-origin streams and embedded audio/silence. Final-source MPEG-4/H.264/H.265 MP4 presets include project/720p/1080p/UHD resolution and requested24/25/30/60 FPS. Automatic selection actually initializes NVENC/QSV/AMF and falls back to an available software encoder; this is compatibility discovery, not a fastest-encoder scheduler. Unsupported graph/effect/HDR/format families fail explicitly. Exact installed FFmpeg configuration and codec patent/distribution rights require separate review. See ADR0015 and research/UHD_EXPORT.md.

Source identity uses streaming BLAKE3 before/after probing and rendering; same-size replacements are rejected. Pre/post hashes do not defeat hostile change-and-restore races. Native typography direction is Parley with one shared layout/glyph scene and CPU reference renderer, subject to comparison with cosmic-text and measured Vello compatibility; resvg is static SVG input and libass optional ASS interoperability. Audio retains FFmpeg decoding; the native preview crate adds bounded playback, monitor gain and CPAL device output, while professional mixing, persistent waveform caching and Rubato conversion remain staged. Preview clock accuracy requires measured tests; device presence alone is not synchronization evidence. These libraries are researched rather than added blindly. GPU media choices (NVENC/NVDEC, QSV, AMF and platform alternatives) require actual codec/device initialization, decoded-output verification and app-level benchmarks; the baseline CPU preset remains available. Watchers are hints; cache DAG identity, quotas and safe cleanup need a separate measured slice. See ADRs 0005–0006.

Creative scene direction: versioned declarative semantic scenes compile into stable editable Rust objects on the same timeline, supporting theme/layout/safe-area constraints, multilingual titles, vectors, shapes/connectors, keyframes/easing, cue-based narration synchronization and scene-local revisions. Low-level controls remain available. Optional Manim Community and Motion Canvas adapters retain source specifications/editable parameters/provenance while registering generated assets; they do not become separate authoritative timelines. SVG, Lottie/dotLottie and formula interchange are scoped/audited independently. Creative quality inspection will expose low-resolution scene previews, key frames/contact sheets, measured timing/asset/text/audio/black-frame checks and bounded review iterations. Artistic choices stay with the external agent; automated reports cannot certify professional quality or monetization. The 60-second neural-network explainer, travel Reel and Blender technical demo must remain editable and report actual time/interventions/resources/reliability. See the authoritative vision addendum and ADR 0009.

Diagnostics now use structured tracing JSON on stderr and correlation/timing fields without media contents or raw command arguments in trace events. CLI success/error envelopes expose request IDs. Cargo-deny gates advisories, licenses, bans and sources while exempting unpublished proprietary workspace code from public-license inference. Other test tools are staged as documented in ADR 0007. Windows distribution direction is per-user NSIS then optional MSI, separate Authenticode/updater signatures, verified TLS updates, preserved user/model stores and migration-aware rollback; no installer/signing/publishing is implemented or purchased. CLI capability introspection exposes implemented scope, prerequisites and explicit unknown telemetry; broader registry contracts remain staged; native distribution is ADR0011 and capability history is ADR0008.

Long term: renderer abstraction with wgpu/WGSL and CPU fallbacks; shared frame/effect evaluator for export and preview; Rust audio clock/mixer; native egui/eframe Studio with docking and shared egui-wgpu resources. The preview worker decodes outside the UI loop; CPU RGBA uploads share the eframe GPU device, without a hardware zero-copy claim. Content-addressed cache keys include input hashes, parameters, backend versions and settings. Hardware scheduling reserves RAM/VRAM, prioritizes playback and represents unavailable telemetry as unknown. Model installations are pinned, checksum verified and atomic. Blender is an optional trusted scene-spec worker; project files never supply executable code.

Undo/redo are shared strict typed commands resolved by the authoritative Store. Each ordinary atomic batch is one logical step; restore creates a new increasing durable revision, retains all history/receipts and rebuilds FTS in the same transaction. A new edit after undo discards logical redo availability without deleting audit rows. No graph/storage migration is needed for this slice. Metadata reconstruction is linear, bounded to100,000 records/64MiB command data; it loads one bounded target snapshot. History listing and integrity/backup scans retain their documented scaling limits. Studio derives advisory availability off the UI loop and still sends its current expected revision. ADR0017 and testing/HISTORY_CLIPBOARD.md record tests and limitations.

Clipboard v1 contains only project/media IDs, verified source digest, rational rate and integer source range, with strict parsing and a16KiB bound. Authoritative PasteClip binds the full payload to the receipt and validates against the current graph. CLI accepts an explicit position; native paste appends to the timeline. Same-project transfer is implemented; cross-project asset transfer remains staged. Native Undo/Redo controls and Copy/Paste route through the same service, without a separate Studio history cursor. Physical keyboard and OS clipboard acceptance remain distinct from the executed native command/preview workflow.

Project-local media aliases use an additive optional field with defaulting and omission when absent, preserving old no-alias snapshots/index integrity for new readers. Old binaries reject alias-bearing snapshots and new history commands; forward compatibility is not claimed. RenameMedia requires an explicit string or null reset and shares one display helper across clients, cards/timeline/Inspector. RemoveMedia rejects current clip references and removes only that imported UUID; an explicit delete-clips/remove batch is one undoable transaction. Source files and catalogue entries remain unchanged. Aliases append to FTS only when present. Composition graph changes still require an explicit historical migration; label metadata does not silently rewrite history. See ADR0018.

Ordinary Studio UI embeds the audited Inter Regular face once at default weight/optical coordinates, retaining existing glyph fallbacks and technical monospace text. Its unmodified font and OFL notice are available in the reviewed catalogue and native diagnostics. This UI font is separate from future editable scene typography and export layout. Export groups resolution and video settings, keeps filename/destination/action outside a bounded settings scroll, and puts encoder/bitrate under Advanced. Normal Studio starts at1080p/H.264/automatic hardware selection with software fallback; CLI and ordinary synthetic smoke defaults retain their compatible MPEG-4 policy. Project drawer exposes name/canvas/size/rate/duration, while paths/revisions and direct-path tools stay collapsed or advanced. Research/acceptance: STUDIO_TYPOGRAPHY and STUDIO_POLISH.

See ADRs for decisions and provisional alternatives. Models, advanced audio, effects, smart caching and production resource scheduling remain staged. Measured acceptance and remaining limitations belong in PROGRESS and the native verification documents.

Priority order: verify this CLI/media/database foundation → authenticated project service → live synchronized Studio → native scenes/text/vectors/keyframes → reusable explainer components/narration alignment/scene review → editable Demo A. Traditional editor breadth proceeds alongside creative capabilities rather than delaying them. Optional Blender supports Demo C; approved supplied media/color/transitions/captions support Demo B.

Performance policy: measure practical bottlenecks before selecting native C/C++/SIMD/CUDA/Vulkan alternatives. Rust's project graph remains authoritative; MLT is an optional researched backend/reference, not a replacement. GUI rendering, decode workers, timeline evaluation, export jobs and optional AI have separate lifetimes and budgets. No handwritten Assembly or unsafe performance shortcuts are introduced. The Win32 service transport/launcher module's reviewed unsafe blocks are confined to required Win32 security FFI, with ownership/alignment/cleanup contracts; they do not optimize editing or rendering. Hardware codec/texture interop, proxies and incremental rendering remain benchmark-gated. See ADR0012 and native benchmark records.
