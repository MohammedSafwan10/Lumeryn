# Lumeryn architecture

Authoritative requirements: [PRODUCT_SPEC](docs/PRODUCT_SPEC.md). Publisher branding is NEXDARK LABS, a pending sole-proprietorship brand, not a claim of registered incorporation.

Primary users are people with little editing knowledge who brief an external agent in ordinary language. The agent directs narrative/storyboard/assets, performs edits, reviews actual output and makes bounded refinements. Lumeryn executes deterministic creative/editing operations and exposes the same editable project to professional humans in Studio. Autonomous, Review and Refine, and Professional Manual Editing are workflows over one engine. No built-in competing agent or MCP. Animated educational explainers are an early flagship capability, not an artistic-quality guarantee.

The workspace starts with `lumeryn-core` and `lumeryn-cli`. The core owns validated project types, rational frame evaluation, persistence and controlled media workers. The CLI translates semantic commands and emits JSON. No UI code owns editing rules.

Initial flow: CLI → typed command → validation → SQLite transaction → versioned project snapshot/history. Render reads a committed snapshot, evaluates clips in Rust and invokes an isolated media adapter. Original assets are references and remain immutable. Stable UUIDs identify project, tracks, media and clips. Timeline durations and positions are integer frames at a rational project rate; source frame ranges use an explicitly compatible source rate.

Persistence: versioned SQLite with WAL, FULL durability, foreign keys, bounded lock waits, one transaction per mutation, revision conflict checks and idempotent receipts. The first implementation uses a small JSON graph in transactional rows; later indexed tables can be migrated without changing public commands. SQLite serializes headless writers initially. The authenticated service becomes the sole writer before Studio ships. CLI and Tauri clients then connect to its revision event stream; reconnect requests missing revisions or a snapshot. Direct database writes will not be a parallel Studio path.

Each portable project owns `project.lumeryn`. There is no PostgreSQL, Firebase, Appwrite or mandatory cloud store. The independent global app database is staged for installed-model manifests, settings, hardware benchmark profiles and shared metadata; it never becomes necessary to reopen a project. Large media/model/cache bytes stay on disk. New project storage includes verified FTS5 metadata search; transcript indexing follows actual transcription storage. An optional local vector index remains unselected pending CLIP/corpus recall/latency/memory/Windows benchmarks. Graph schema and storage migration version are separate. Explicit transactional migration, integrity/history/index checks, and `VACUUM INTO` backups are implemented; cross-directory backups rebase relative references to the same original assets and do not copy media. See ADR 0001.

Media: user-installed FFmpeg/ffprobe via argument arrays, local files only, bounded output and timeouts. Baseline export is a narrow CPU prototype: one video track, contiguous clips, exact matching CFR sources, native MPEG-4 Part 2/AAC MP4, embedded audio or silence, normalization to project dimensions. Reject unsupported layouts instead of approximating them. Codec compatibility and patents require review; selecting native codecs does not relicense the installed FFmpeg binary.

Source identity uses streaming BLAKE3 before/after probing and rendering; same-size replacements are rejected. Pre/post hashes do not defeat hostile change-and-restore races. Native typography direction is Parley with one shared layout/glyph scene and CPU reference renderer, subject to comparison with cosmic-text and measured Vello compatibility; resvg is static SVG input and libass optional ASS interoperability. Audio retains FFmpeg decoding, then stages a deterministic Rust sample-index mixer/waveform pipeline, Rubato conversion and CPAL WASAPI device output with measured presentation clocks. These libraries are researched rather than added blindly. GPU media choices (NVENC/NVDEC, QSV, AMF and platform alternatives) require actual codec/device initialization, decoded-output verification and app-level benchmarks; the baseline CPU preset remains available. Watchers are hints; cache DAG identity, quotas and safe cleanup need a separate measured slice. See ADRs 0005–0006.

Creative scene direction: versioned declarative semantic scenes compile into stable editable Rust objects on the same timeline, supporting theme/layout/safe-area constraints, multilingual titles, vectors, shapes/connectors, keyframes/easing, cue-based narration synchronization and scene-local revisions. Low-level controls remain available. Optional Manim Community and Motion Canvas adapters retain source specifications/editable parameters/provenance while registering generated assets; they do not become separate authoritative timelines. SVG, Lottie/dotLottie and formula interchange are scoped/audited independently. Creative quality inspection will expose low-resolution scene previews, key frames/contact sheets, measured timing/asset/text/audio/black-frame checks and bounded review iterations. Artistic choices stay with the external agent; automated reports cannot certify professional quality or monetization. The 60-second neural-network explainer, travel Reel and Blender technical demo must remain editable and report actual time/interventions/resources/reliability. See the authoritative vision addendum and ADR 0009.

Diagnostics now use structured tracing JSON on stderr and correlation/timing fields without media contents or raw command arguments in trace events. CLI success/error envelopes expose request IDs. Cargo-deny gates advisories, licenses, bans and sources while exempting unpublished proprietary workspace code from public-license inference. Other test tools are staged as documented in ADR 0007. Windows distribution direction is per-user NSIS then optional MSI, separate Authenticode/updater signatures, verified TLS updates, preserved user/model stores and migration-aware rollback; no installer/signing/publishing is implemented or purchased. CLI capability introspection exposes implemented scope, prerequisites and explicit unknown telemetry; broader measured registry contracts are staged in ADR 0008.

Long term: renderer abstraction with wgpu/WGSL and CPU fallbacks; shared frame/effect evaluator for export and preview; Rust audio clock/mixer; Tauri2/Svelte5/TypeScript Studio; measured native-preview prototypes before surface selection. Content-addressed cache keys include input hashes, parameters, backend versions and settings. Hardware scheduling reserves RAM/VRAM, prioritizes playback and represents unavailable telemetry as unknown. Model installations are pinned, checksum verified and atomic. Blender is an optional trusted scene-spec worker; project files never supply executable code.

See ADRs for decisions and provisional alternatives. GPU, Studio, IPC, models, advanced audio, effects, caching, undo/redo and production scheduling are planned, not shipped by the first slice.

Priority order: verify this CLI/media/database foundation → authenticated project service → live synchronized Studio → native scenes/text/vectors/keyframes → reusable explainer components/narration alignment/scene review → editable Demo A. Traditional editor breadth proceeds alongside creative capabilities rather than delaying them. Optional Blender supports Demo C; approved supplied media/color/transitions/captions support Demo B.
